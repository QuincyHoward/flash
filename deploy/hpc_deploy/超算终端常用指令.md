## 1. 作业查询与状态

### 查看运行时间/状态等（多日期范围, 北京 <超算账号> 示例）

```bash
sacct -u <超算账号> -S 2026-08-25 -E 2026-09-10 \
  --format=jobid,jobname,partition,alloccpus,start,end,elapsed,state,nodelist -X
```

```bash
sacct -u <超算账号> -S 2026-08-25 -E 2026-09-10 \
  --format=jobid,jobname,partition,alloccpus,start,end,elapsed,state,nodelist -X
```

- `-S/-E`: 起止日期; `-X`: 只显示主作业 (不含作业步); `--format` 自定义列。
- 常用 state: `COMPLETED` / `RUNNING` / `FAILED` / `TIMEOUT` / `CANCELLED`。
- 宁夏 <超算账号> 同理: `sacct -u <超算账号> -S <日期> -E <日期> ...`。

### 只看当前在跑/排队的作业

```bash
squeue -u <超算账号>                     # 自己的队列
squeue -u <超算账号> -o "%.10i %.20j %.8T %.10M %.6D %R"   # 带预计剩余时间/节点
squeue --start                        # 预计开始时间 (排队作业)
```

### 单个作业历史

```bash
sacct -j 123456 --format=jobid,elapsed,state,maxrss,maxdiskread,maxdiskwrite
sacct -j 123456.0 --format=...       # .0 = 主作业步 (资源统计在作业步上)
```

## 2. 作业提交与取消

```bash
sbatch FirstFLASH.sh                  # 提交 (脚本内 #SBATCH 指令生效)
sbatch --partition=v6_384 FirstFLASH.sh   # 命令行覆盖分区
scancel 123456                        # 取消作业
scancel -u <超算账号>                    # 取消自己全部作业 (慎用)
sbatch --test-only FirstFLASH.sh      # 只校验不提交 (检查 #SBATCH 语法/分区)
```

**sbatch 铁律 (本项目实测)**:

- `#SBATCH --output=~/{dir}/x` **波浪号不展开** → 输出进字面 `~` 目录;
  一律用**相对路径** (相对 sbatch 提交目录) 或 `$HOME`。
- 脚本先 `cd` 到工作目录再 sbatch; marker/输出校验路径必须与之一致。
- `#SBATCH` 指令必须在**前部连续注释块**内, 中间插入普通行会截断解析
  (报 `Invalid directive found in batch script`)。

## 3. 作业详情与诊断

```bash
scontrol show job 123456              # 全量详情 (工作目录/分区/资源/TIME_LIMIT)
scontrol show job 123456 | grep -E "JobName|WorkDir|RunTime|TimeLimit|NumCPUs|StdOut"
scontrol listpids 123456              # 作业内进程 PID (部分系统支持)
sstat -j 123456 --format=jobid,maxrss,avecpu   # 运行中作业步资源
```

## 4. 节点与分区信息

```bash
sinfo                                 # 分区总览 (首行可能是 inact 分区, 别盲取)
sinfo -p v6_384                       # 指定分区
sinfo -p v5_192 -o "%.12P %.6a %.10s %.4N"   # 含状态统计
scontrol show node <节点名>            # 节点详情 (CPU/内存/状态)
sinfo -N -p v6_384                    # 逐节点状态 (idle/alloc/mix/drain)
```

分区状态: `up` 可用; `inact`/`drain` 不可用 — 探测分区时过滤 `avail=up`。

## 5. 实时日志跟踪

```bash
tail -f slurm-123456.out              # 跟踪 sbatch 输出 (Ctrl-C 退出, 不杀作业)
tail -n 100 slurm-123456.out          # 看最后 100 行
less +F slurm-123456.out              # less 实时模式 (Shift+F)
grep -c "step:" slurm-123456.out      # 数步数 (FLASH 步进行度)
grep -E "Error|ERROR|Abort" slurm-123456.out | head
```

## 6. 模块与编译环境

```bash
module avail                          # 可用模块 (支持模糊: module avail gcc)
module list                           # 已加载
module load gcc/9.3.0                 # 加载
module purge                          # ★ 慎用 — 会清掉登录环境默认加载的
                                      #   oneAPI 等 (本项目实测教训)
module show gcc/9.3.0                 # 查看模块做了什么 (PATH/LD_LIBRARY_PATH)
which mpif90 && mpif90 --version      # 确认编译链实际生效版本
echo $LD_LIBRARY_PATH                 # 核对运行库路径
```

**本项目已知的运行库坑**:

- BSCC gcc/9.3.0-new 的 lib64 无 `libgfortran.so.5` → 运行时需
  `export LD_LIBRARY_PATH=/public1/soft/miniforge/24.11/lib:$LD_LIBRARY_PATH`。
- BSCC mpif90 wrapper 按 PATH 选 gfortran: 系统 4.8.5 会 ICE, 必须 prepend
  `/public1/soft/gcc/9.3.0-new/bin`。
- `module load` 在非交互/作业脚本 shell 里**不更新环境变量** (modulecmd 缺陷)
  → 脚本内必须显式 `export`。

## 7. 文件传输

```bash
scp local.tgz <超算账号>@<login>:~/     # 上传
scp <超算账号>@<login>:~/flash_output.tgz .   # 下载
rsync -avP --exclude 'plt_*' dir/ <超算账号>@<login>:~/dir/   # 断点续传+排除
tar czf pack.tgz dir/ && md5sum pack.tgz     # 打包+校验 (大文件传输前)
tar xzf pack.tgz
```

注意: 登录节点一般**禁止计算** (编译/运行走 sbatch); 大文件用 `tar` 打包
而非逐文件 scp (连接不稳时快得多)。

## 8. 调试与排错

### 提交失败类

```bash
sbatch --test-only job.sh             # 先校验
scontrol show partition v6_384 | grep -E "MaxTime|MaxNodes|DefMemPerCPU"
```

常见报错:

| 报错 | 原因/对策 |
|------|-----------|
| `Invalid directive found in batch script` | #SBATCH 块被普通行截断, 或行首有空格 |
| `Partition specification is invalid` | 分区名错/不可用, `sinfo` 核对 |
| 作业秒失败且 out 为空 | 检查 `#SBATCH --output` 相对路径与 `cd` 顺序 |
| `qsub: invalid queue` 类 | 用错系统命令 (PBS vs SLURM), 本项目两台均 SLURM |

### 运行失败类

```bash
sacct -j <id> --format=jobid,state,elapsed,maxrss   # 看退 state 与内存峰值
ls -la slurm-*.out                     # 确认输出文件真在提交目录
cat slurm-*.out | tail -50
# FLASH 专项:
grep -E "RUN_EXIT|ERROR|Abort|NaN|Negative" slurm-*.out | head
```

- `CANCELLED by <uid>`: 自己 scancel 或超时被杀。
- `OUT_OF_MEMORY` / `OOM`: 降低单核内存占用或加 `--mem`。
- `TIMEOUT`: `--time` 上限前未完成 (分段 checkpoint 续跑)。

### 交互式快速调试

```bash
salloc -p v6_384 -N 1 --time=00:30:00  # 申请交互节点 (调试编译/短测)
# ... 调试完
exit
```

## 9. 核数经验与注意事项

**核分配多了也不好** — MPI 通信开销+核挤占, 存在最优值; 以短时探测
(`--probe-cores`) 定最优, 不要拍脑袋拉满。

本项目实测记录 (参考):

| 平台/账号 | 配置 | 结果 |
|-----------|------|------|
| 北京 <超算账号> | 40 核 | 约 3 小时 |
| 北京 <超算账号> | 40×4 核 | 进度缓慢 (跨节点通信开销) |
| 宁夏 <超算账号> | 4×48 核 (192) | 约 2 小时 |
| 宁夏 <超算账号> | 48 核 | 约 (探测中) |

**SNBOneCH_ml +ug 0.03µm 探测 (tmax=2e-10, 2026-09-08)**:

| 平台 | 核数 (网格) | dx | WALL_SECONDS | 备注 |
|------|------------|----|--------------|------|
| WSL (本地) | 4 (iProcs=4, nxb=128) | 0.977 µm | 9.8 s | 小规模最优; 核越多越慢 (8核17.8s/16核59.7s/24核121.7s) |
| NC-E <超算账号> | 131 (iProcs=131, -N 3, v5_192 48核/节点) | 0.0298 µm | 3501.9 s (58.4 min) | 首跑遇 IB 瞬时故障 (rc_verbs retry exceeded, 0 步即死), 原样重试成功; ~5.6 s/步 |
| BSCC <超算账号> | 131 (-N 2, v6_384, oneAPI 编译) | 0.0298 µm | **未完成** (164 步被杀 @3h09m) | ~42-66 s/步 (慢 NC-E ~10 倍); @23:50 被外部 CANCELLED (Timelimit=UNLIMITED); 日志见 gr_hypreSolve 不收敛警告 (ierr=256) + dt 下滑 — oneAPI 编译版失稳前兆。**0.03µm 生产跑不可用 BSCC** |

**BSCC 附加教训**: 同一 par/网格, NC-E (gcc/gfortran) 稳定完成而 BSCC
(oneAPI/mpiifort -O2) 出现 hypre 不收敛 + dt 响应下滑 — 跨平台浮点差异
对 SNB 隐式求解器敏感, 平台间结果需做一致性核查 (编译器差异)。
另: UNLIMITED 时限作业也可能被管理员/调度策略取消, 长跑务必
`--time` 显式申请并拆 chk 断点续跑。

注意: +ug 模式核数=块数=分辨率锁定 — 不同核数对应不同 dx/工作量, 各点
不可直接横向比较; 跨 3 节点 SNB 隐式求解通信开销大, 同分辨率下效率低于
单节点。探测用 `--probe-cores` (每点自洽重建 par)。

单节点内多核通常优于跨节点 — 优先 `-N 1` 打满单节点再考虑跨节点。
`-N` 需按分区每节点核数自适应: `sinfo -h -p <分区> -o "%c"` 后
`-N = ceil(ntasks/每节点核数)` (131 任务 @48核/节点 → -N 3)。

### FLASH (SLURM) 作业脚本模板要点

```bash
#!/bin/bash
#SBATCH --job-name=SNBOneCH
#SBATCH --partition=v6_384
#SBATCH --nodes=1
#SBATCH --ntasks=131          # +ug 下必须等于 par iProcs (块数)
#SBATCH --time=02:00:00
#SBATCH --output=slurm-%j.out   # 相对路径! (~ 不展开)

cd $SLURM_SUBMIT_DIR          # 工作目录 = 提交目录
export LD_LIBRARY_PATH=/public1/soft/miniforge/24.11/lib:$LD_LIBRARY_PATH  # BSCC
srun ./flash4 > flash_run.log 2>&1   # 或 mpiexec (与编译时 MPI 一致)
```

- SLURM 环境下优先 `srun` (自动继承分配); 本地编译用哪个 MPI (mpich/openmpi)
  运行就用哪个启动器, 混用会通信异常。
- FLASH 输出 (`plt/chk/log`) 用后即转走, 不占计算节点配额。
