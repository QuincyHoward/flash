# flash 包模块化改造计划（v2 修订稿，2026-10-22）

> 日期：2026-10-22（v1 草案同日；v2 按审核意见修订：①架构表述改为功能模块化分工解耦、
> ②部署模块提升至仓库根目录、③根目录产物统一归入 `artifacts/`）。
> 目标：将 flash 包的**安装部署**与 FLASH 的**各种运行模式**解耦，**按功能模块化分工**，
> 便于后期调用与维护。
> 范围：仓库根目录、`flash/flash/scenarios/`、`flash/flash/flash_run/`。

---

## 0. 现状盘点（改造依据）

| 现状 | 位置 | 问题 |
|------|------|------|
| 安装入口 `start_flash.py`（在线/离线双模式） | 根目录 | 与运行健康检查/三套测试耦合在同一脚本 |
| 造包/离线安装/wheel 护栏 | `scripts/08_offline_install/` | 位于 scripts 层，不随包分发、不可被 API 调用 |
| 超算离线部署链 run_all.py 01–07 | `flash/flash_run/remote/test/scripts/` | 与"测试"混放；部署技能未 CLI 化 |
| 运行三模式执行体（wsl/hpc-remote/hpc-insitu） | `flash/scenarios/runner.py` | **运行逻辑长在场景层**，场景目录本应只管场景 |
| 装置参数硬编码 | 各场景脚本（如 SNBOneCH_m nprocs=131、SNBVTi* 125、account=flash_ssh） | 换装置/换核数需改场景源码 |
| 平台依赖差异 | pyproject 注释、memory、各 README 零散 | 无单一事实源，yt==4.4.0/glibc 锁定等靠人记 |
| **根目录产物散落** | `dist/`、`_dl_test/`、`%SystemDrive%/` 等直接堆在根目录 | 构建产物/临时文件污染根目录，违反"根目录保持简洁" |

## 1. 目标架构（按功能模块化分工，解耦）

三个功能模块**各自独立、经显式接口调用**：
**deploy（安装部署）/ flash_run（运行）/ scenarios（场景）**——
deploy 面向仓库分发与三平台安装；flash_run 面向运行方式与超算操作；
scenarios 面向物理场景，通过参数控制 flash_run 的行为。便于后期独立调用与维护。

```
仓库根/
├── pyproject.toml           # 依赖意图唯一事实源（1.1）
├── deps_lock/               # 新增：三平台锁定文件（由基线生成）
│   ├── requirements-win.txt
│   ├── requirements-wsl.txt
│   ├── requirements-hpc.txt
│   └── generate_locks.py    # 从基线 + 平台差异表生成，防手工漂移
├── DEPENDENCIES.md          # 新增：三平台版本差异表（根目录，1.1 要求）
├── deploy/                  # ★ 新增（根目录一级）：安装部署模块
│   ├── README.md            #   三平台离线部署 SOP
│   ├── env_spec.py          #   平台差异规格（机器可读源，供 generate_locks 与 doctor 使用）
│   ├── build_wheelhouse.py  #   造包（Windows 本地）
│   ├── build_wheelhouse_linux.py  # 交叉造包（Linux glibc2.17，供超算）
│   ├── build_wheelhouse.bat / install_offline.bat
│   ├── install_offline.py   #   --no-index 离线安装（三平台共用）
│   ├── doctor.py            #   环境/安装自检（收编 test_offline_install 的健康检查部分）
│   ├── wheel_leak_audit.py  #   wheel 护栏（原样迁移）
│   └── hpc_deploy/          #   超算离线部署链（原 remote/test/scripts 01–07 收编）
│                           #   产出可上传超算的自包含脚本（ASCII、LF），
│                           #   本地可驱动、超算登录节点可直接执行
├── start_flash.py           # 瘦身：仅安装/部署调度薄壳，转发到 deploy/
├── artifacts/               # ★ 新增：根目录所有生成产物统一归此，不污染根目录
│   ├── dist/                #   wheel/sdist（替代根目录散落的 dist/）
│   ├── wheelhouse/          #   离线包（原 offline_pkg/ 归并）
│   └── logs/                #   构建/安装/审计日志与报告（原 *_dl_test 等归并）
└── flash/                   # pip 包本体（flash-sim）
    ├── flash_run/           # 运行模块：三种运行模式的调用关系唯一归属（第 2 条）
    │   ├── env/             #   环境管理（现有，保留；装置默认值下沉至此）
    │   ├── modes/           # ★ 新增：由 scenarios/runner.py 迁入
    │   │   ├── wsl.py       #     wsl 模式执行体
    │   │   ├── hpc_remote.py#     hpc-remote（本机驱动 → SSH → 超算）
    │   │   └── hpc_insitu.py#     hpc-insitu（登录节点直跑）
    │   ├── hpc.py           # ★ 新增：超算技能统一 CLI（本地、超算两侧可调）
    │   └── remote/          #   现有 paramiko 层（deploy/slurm_control/route_tester 保留）
    └── scenarios/           # 场景模块：只做场景搭建 + 参数覆盖（第 3 条）
        ├── runner.py        #   瘦身为兼容壳：re-export flash_run.modes，老脚本零破坏
        └── ...（场景脚本不再出现 SSH/sbatch/路径细节）
```

**模块间接口约定**：
- `scenarios → flash_run`：仅经 `run_scenario(...)` / `resolve_run_mode(...)` 显式接口 + 参数覆盖；
- `flash_run → deploy`：仅依赖 `deploy/env_spec.py` 的平台差异规格（机器可读）；
- deploy 不依赖上两层；`deploy/` 与 `scripts/` 均不入 wheel（sdist/wheel exclude 显式排除）。
- ★ `artifacts/` 同步写入根 `.gitignore` 与 `pyproject.toml` exclude（**成对维护铁律**）。

## 2. 需求 1.1 —— 三平台依赖统一

1. **版本意图唯一化**：`pyproject.toml` 仍是语义化声明处；新增 `deps_lock/` 生成精确版本。
2. **基线策略**：三平台取**交集版本**（numpy/h5py/matplotlib/pandas 等尽量同版本）；
   平台约束只在差异层体现，已知的必须差异：
   - HPC(NC-E)：glibc2.17 锁定 `pandas==2.3.2 / h5py==3.14.0 / pillow==12.2.0 / yt==4.4.0`（4.3.1 SIGSEGV）；
   - WSL：`FLASH_VENV_DIR` 环境变量约定；venv 路径隔离；
   - Windows：无原生 FLASH，仅 Python 侧依赖（造包/分析/SSH 驱动）。
3. **差异显性化**：根目录 `DEPENDENCIES.md` 表格列出：包名 | 基线版本 | Win | WSL | HPC | 差异原因。
   任何"如果不同需要在根目录明确给出"的差异，均落到此表 + `deploy/env_spec.py` 双处一致（env_spec 为机器可读源，md 由其生成或同步校验）。
4. **护栏**：`generate_locks.py` 校验三份 lock 与 `env_spec.py` 一致；不一致即报错。

## 3. 需求 1.2 —— 三平台离线部署与安装测试（验收标准）

复用现有资产（wheel_leak_audit、build_wheelhouse*.py、install_offline.py、test_offline_install.py 124 项、超算 run_all.py 01–07），逐平台验收：

| 平台 | 步骤 | 通过标准 |
|------|------|---------|
| Windows | `deploy/build_wheelhouse.bat` 造包 → SHA256 校验 → `install_offline.bat` → `doctor.py`（原 test_offline_install） | 124 项全绿 + wheel_leak_audit 通过（MB 级 wheel） |
| WSL | 离线 wheelhouse 装 `FLASH_VENV_DIR` 指定 venv → 三套测试 | 全绿 + `ch_center` 一键流程 gen_checker 自检通过（fresh clone 验证） |
| 超算 NC-E | 交叉造包（glibc2.17）→ 上传 → `deploy/hpc_deploy/` run_all.py 01–07 | 三套测试 132/83/45 全绿 + 极短场景冒烟（tmax=1e-11） |

注意沿用既有铁律：`pip download` 跳过本体 + SHA256 指纹校验；fresh-clone 测试必做；wheel exclude 成对维护。

## 4. 需求 2 —— flash_run 运行模块 + 超算技能脚本化

1. **运行逻辑迁移**：`scenarios/runner.py` 中三种模式的执行体迁至 `flash/flash_run/modes/`；
   `scenarios/runner.py` 保留同名 re-export（`run_scenario`、`resolve_run_mode`、`RUN_MODES` 等），**30+ 现有场景脚本零修改可跑**。
2. **超算技能 CLI 化**（新 `flash/flash_run/hpc.py`，可本地驱动也可超算 in-situ 调用）：
   ```
   python -m flash.flash_run.hpc submit   --par xxx.par --nprocs 131 --account flash_ssh
   python -m flash.flash_run.hpc status   --job <id>        # 内含 squeue 查询约定
   python -m flash.flash_run.hpc wait     --job <id> [--timeout s]
   python -m flash.flash_run.hpc cancel   --job <id>
   python -m flash.flash_run.hpc download --remote <dir> --local <dir> [--pattern "*.h5"]
   python -m flash.flash_run.hpc route-test                    # 9 路由择优
   python -m flash.flash_run.hpc deploy   [--wheelhouse D]     # 超算侧离线部署入口
   ```
   实现上包装现有 `FlashRemoteDeploy` / `slurm_control` / `route_tester`，断点续跑 `hpc_task.json`、SSH 串行限制等既有约定保留。
3. **超算侧入口固化**：根目录 `deploy/hpc_deploy/` 产出可上传的 `hpc.sh + hpc.py` 自包含脚本（ASCII、LF），既支持本地 `python -m` 驱动，也可在超算登录节点直接执行。

## 5. 需求 3 —— 场景模块去运行化

1. 场景脚本只保留：SCENE VARS（物理参数）+ **运行覆盖参数**（`RUN_MODE` 默认值、nprocs、account、tmax 等），运行一律经 `run_scenario(...) → flash_run.modes`。
2. 装置默认值收敛到 `flash/flash_run/env/resource_config.py`（如 SNBOneCH_m=131 核、SNBVTi*=125 核、account 名）；场景仅在需要时以参数覆盖，不再硬编码。
3. 批量套件（run_ml_suite / run_sic_suite）改为统一入口 + 参数透传，不复制运行细节。
4. 迁移顺序：兼容壳先行 → 逐场景删除内联运行细节 → gen_checker 增加一条「场景内禁止出现 sbatch/ssh/绝对路径」的检查规则。

## 7. 实施阶段（每阶段独立可验收）

- **Phase 0（0.5 天）**：产出 `DEPENDENCIES.md` 依赖矩阵初版 + 精确盘点 scripts/08 与 remote/test/scripts 中待迁移文件清单 → **交你确认后动手**。
- **Phase 1 依赖统一**：`deps_lock/` + `generate_locks.py` + 差异表；Windows/WSL 各装一遍验证版本一致。
- **Phase 2 部署收编 + 根目录清理**：建根目录 `deploy/`（迁移 08_offline_install + 部署链脚本）；建 `artifacts/` 并归并根目录散落产物（`dist/`、`offline_pkg/`、`_dl_test/`、`%SystemDrive%/` 等，**先备份后移动**）；`start_flash.py` 瘦身为薄壳；.gitignore/pyproject 成对更新；wheel_leak_audit 回归。
- **Phase 3 运行迁移**：runner.py 执行体 → `flash_run/modes/`；新增 `hpc.py` CLI；兼容壳保证老脚本可跑；fresh-clone 验证。
- **Phase 4 场景去运行化**：装置参数下沉 resource_config；逐场景清理内联细节；gen_checker 新规则。
- **Phase 5 三平台联测 + 文档定稿**：按 §3 表逐平台验收；更新全部 md；Gitee 提交。

## 8. 风险与约束（已知铁律）

- wheel/sdist exclude 必须与 .gitignore **成对维护**；`private/` 禁止整目录排除（先查 `git ls-files`）。
- 根目录产物归并（artifacts/）属移动操作：**先备份、小批量、移动后逐一核验**；`offline_pkg/` 若被脚本/文档按旧路径引用，需同步更新引用或保留重定向说明。
- 场景脚本兼容是硬要求：`python CHTi1.py` 等直跑方式在 Phase 3/4 期间不得中断。
- 超算 SSH 限并发：联测脚本串行执行；后台任务 `PYTHONUNBUFFERED=1`。
- `pip download` 同名包覆盖陷阱：download 清单跳过 flash-sim 本体，用 SHA256 指纹校验。
- E: 盘间歇不可见：改造期间 git 提交前先 `git status` 核对，推送用 `git_push.py` 并以 `git ls-remote` 判定成败。
