# 14 · 审计报告

> 审计报告不是"运行副产品"，而是**可以被程序消费的证据**。
> 阶段 B 的 `infer-unrecognized` 就是读 `audit_all.*.csv` 来挑未决文件的
> （见 [02 §3.4](02_两段式执行.md)）—— 这个设计选择决定了报告的字段必须**机器可读**。

---

## 1. 三份报告，三种用途

| 文件 | 格式 | 用途 |
|---|---|---|
| `audit_all.<ts>.csv` | UTF-8 with BOM + `,` | Excel / pandas 直接分析；**阶段 B 的输入** |
| `audit_all.<ts>.json` | UTF-8，indent=2 | 结构化嵌套（`by_status`/`by_family`/`snapshots`）；CI 断言 |
| `audit_all.<ts>.md` | UTF-8 | 人读：8 个分节，含问题清单与闸口结论 |

时间戳 `%Y%m%dT%H%M%S`（本地时间）—— 按文件名排序 = 按生成顺序排序。

### 1.1 CSV 用 `utf-8-sig` 的原因

Excel 双击打开 CSV 不看 BOM 就按系统 ANSI（中文 Windows 是 GBK）解码，
中文列名会乱码。加 BOM 后 Excel 识别为 UTF-8。
`reporting.write_csv` 固定用 `utf-8-sig`。

## 2. `audit_all.*.md` 的八节结构

| 节 | 内容 | 读者要回答的问题 |
|---|---|---|
| 头部 | 来源、UTC、样本数、耗时、**闸口结论** | 能不能信这份报告？ |
| §1 | 按 `status` 计数 | 解了多少、跳了多少？ |
| §2 | 按 `family` 计数（**实际使用的解析器**） | 哪几个解析器在扛活？ |
| §3 | 按 `dispatch_source` 计数 | 声明是从哪来的？ |
| §4 | 按 `declared_family` 计数 | 声明的分布与 §2 差多少？（差 = 候选回退在起作用） |
| §5 | 按 `unit_source` 计数 | 单位是声明来的还是默认的？ |
| §6 | **问题文件清单** | 哪些文件出问题了？为什么？ |
| §7 | `count_mismatch` 明细（含 `header_raw`） | 计数不符的**原始表头文本**是什么？ |
| §8 | 成功但有告警的文件 | 哪些"成功"其实有隐患？ |

★ §7 里带 `header_raw` 是刻意的：计数不符时，
最需要看的就是**表头那一行的原始字节**。把它直接印在报告里，
免去"再跑一遍 grep"的往返。

### 4.1 ★ 第 7 条 bug 的完整故事：报告自洽但数据丢了

```
ATOMIC/Al.txt                          → ATOMIC__Al.h5
ATOMIC/Al.NoFree                       → ATOMIC__Al.h5   ← 覆盖
ATOMIC/Al.AvSqFree                     → ATOMIC__Al.h5   ← 覆盖
ATOMIC/Al.GrayOpacity_PLANCK           → ATOMIC__Al.h5   ← 覆盖
ATOMIC/Al.GrayOpacity_ROSSELAND        → ATOMIC__Al.h5   ← 覆盖
ATOMIC/Al.MultiGroupOpacity_PLANCK     → ATOMIC__Al.h5   ← 覆盖
ATOMIC/Al.MultiGroupOpacity_ROSSELAND  → ATOMIC__Al.h5   ← 覆盖
```

`Path('ATOMIC/Al.NoFree').stem == 'Al'` —— 于是 7 个文件共享一个输出名。
全树统计：**78 个名字被复用，222 个文件被覆盖**。

★ **为什么这个 bug 特别值得记下来**：

| 检查手段 | 能发现吗 | 原因 |
|---|---|---|
| `audit` | ❌ | 不写 h5 |
| `identify` | ❌ | 不写 h5 |
| `convert-all` 的 `n_failed` | ❌ | 覆盖**不报错**，`write_material_h5` 每次都"成功" |
| 异常与日志 | ❌ | 无异常、无 warning |
| **`n_written` 与盘上文件数对账** | ✅ | 992 ≠ 770 |

**唯一**能发现它的手段是"报告里的数 与 磁盘上的事实 对账"。
所以修复不只是改命名，还**新增了一条对账断言**：

```python
n_on_disk = len(list(od.glob("*.h5")))
if n_on_disk < n_written:
    msg = (f"⚠️ h5 命名冲突：报告 n_written={n_written}，"
           f"但盘上只有 {n_on_disk} 个 .h5 —— {n_written - n_on_disk} 个被覆盖！")
```

并写进报告的头部（`对账: 盘上 .h5 数 == 已写数 → ✅ 通过`）、
JSON（`n_h5_on_disk` / `reconciled`）与返回值。

这就是 [§7 报告即接口](#7-报告即接口) 的反面教材：
**报告如果不与外部事实对账，它可以长得完全正常却掩盖 222 个文件的丢失。**

### 4.2 为什么 `agree_structure` 是必要的而不是"和稀泥"

`hyades_eos` 与 `hyades_opacity` 共用 `L = 2 + nr + nt + 2·nr·nt`，
反演**无法**区分，于是 36 个 `hyades/Opacity/opc_*.dat` 会落进
`order_mismatch`，把上面那 4 条真信号淹掉。

结构等价组的陈词必须**可验证**：
`test_struct_equiv_groups_share_a_count_formula` 用
`parsers.base.PAYLOAD_LAYOUTS` 检查组内家族在多个 `(nr,nt,ng)` 上
计数**逐值相等** —— 否则测试失败。这样"结构等价"就不是一句免责声明，
而是一个被断言守住的事实。

### 4.3 一次演练：如果只看 `audit` 会漏掉什么

| 缺陷 | `audit` | `identify` | `convert-all` / `plot-all` |
|---|---|---|---|
| `.INV` 被判 `feos_aux` | ❌ 计数可能恰好自洽 → 报 `ok` | ✅ `conflict` | — |
| `.sesame` 退化成 `generic_curve` | ❌ `generic_curve` 永远"成功" | ✅ `conflict` | — |
| `hyades/**.dat.feos` 退化 | ❌ 同上 | ✅ `conflict` | — |
| `Al_etc.dat` 键撞车 | ❌ 不写 h5 | ❌ 不写 h5 | ✅ `n_failed=1` |
| 退化网格范围 | ❌ 不建网格 | ❌ 不建网格 | ✅ `ValueError` 中断 |
| **h5 命名覆盖** | ❌ | ❌ | ✅ **`n_written` 与磁盘对账** |

★ 四种手段**各管一段**，缺一不可：

```
audit        → 覆盖率与结构自洽（1214 个文件"能不能读"）
identify     → 家族判定的正确性（"读对了没有"）
convert-all  → 下游可用性（"写得出吗"）
对账          → 产出与事实一致（"写出来的东西还在吗"）
```

**这是本项目最重要的一条方法论**：每个阶段都有盲区，
盲区只能被**另一个阶段**或**与外部事实的对账**覆盖。
"报告自洽"永远不等于"结论正确"。

## 5. 报告头部强制字段

```python
reporting.md_header(title, source, total, extra=[...])
# → - 数据来源: `...`
#   - 生成时刻 (UTC): `2026-09-14T06:25:12Z`
#   - 样本总数: **1214**
#   - 工具: `eosop_pro 0.1.0` / schema `1.0`
```

四条**强制**字段，缺一不可：

| 字段 | 为什么必须有 |
|---|---|
| **数据来源**（绝对路径） | 世界上有多个 `matter++` 副本，必须知道是哪一份 |
| **生成时刻（UTC）** | 源数据可能被改动；结论只对那个时刻的字节有效 |
| **样本总数** | 计数类结论（百分比）的分母 |
| **工具版本 + schema 版本** | 换了版本后结论可能变；必须能对齐 |

`reporting` 提供三个写出器 + 两个渲染器：

```python
write_csv(path, rows, columns=None)    # 列顺序：首次出现的顺序
write_json(path, obj)
write_md(path, text)
md_header(title, source, total, extra=())
md_table(rows, columns, max_rows=None, shorten_to=70)
counter_table(counter, key_name, value_name, top=None)
```

`md_table` 的 `max_rows` + `shorten_to` 是**防止报告膨胀**的关键：
`audit_all` 的 `snapshots` 有 1214 行，全渲染会得到几 MB 的 Markdown。
默认截断到 150 行并注明"共 N 行，仅显示前 150 行"。

### 5.1 `convert_all` 的关键字段

```
已写 h5 : N   跳过 : M   失败 : K
总体积  : X MiB    耗时 : T s
```

★ **`n_failed` 必须是 0 才算健康**。`n_skipped` 不为 0 是正常的
（不可解析的文件被登记跳过，不中断整批）。

**一个文件出错不会中断整批**。

### 6.1 ★ 对账：报告的数 vs 磁盘上的事实

`convert_all` 在生成报告前会做一次**与磁盘对账**：

```python
n_on_disk = len(list(od.glob("*.h5")))
if n_on_disk < n_written:
    msg = (f"⚠️ h5 命名冲突：报告 n_written={n_written}，"
           f"但盘上只有 {n_on_disk} 个 .h5 —— {n_written - n_on_disk} 个被覆盖！")
```

并写进三处：报告头部（`对账: 盘上 .h5 数 == 已写数 → ✅ 通过`）、
JSON（`n_h5_on_disk` / `reconciled`）、返回值。

★ **这条对账是本项目唯一能发现"静默覆盖"的手段**（见 [§4.1](#41--第-7-条-bug-的完整故事报告自洽但数据丢了)）：
`n_failed=0`、无异常、无 warning，报告自洽 —— 只有报告的数与磁盘的事实
不一致时才暴露。

### 6.2 报告目录的保留策略（`prune-reports`）

报告文件名带时间戳 → **每跑一次就多一份**。跑一遍全流程 + 几轮测试后，
`outputs/reports/` 会迅速膨胀（实测一次测试套件能新增十多个文件），
"最新结论"被淹没。

```bash
python -m eosop_pro.cli prune-reports              # 每类只留最新 1 批
python -m eosop_pro.cli prune-reports --keep 3     # 留 3 批
python -m eosop_pro.cli prune-reports --dry-run    # 只列不删
```

三条纪律（由 `test_prune.py` 的 11 个测试守住）：

| 纪律 | 理由 |
|---|---|
| **最新一批永不删**，`--keep 0` 也当 1 | 删掉最新批 = 删掉结论 |
| **固定名报告永不碰**（`zeff_inventory.*` / `type_conflict.*`） | 它们每次覆盖，本就不堆积 |
| 一次运行的 `csv`/`json`/`md` **同进同出** | 共享时间戳，拆开就残缺 |

只处理 `csv/json/md`；`h5`/`png`/子目录一律不动。

`run_all.bat` 的第 9 步就是这个（在测试之前跑，顺手清干净）。

`infer-unrecognized` 默认走这条路（`source="audit-report:<name>"`），
只有 `--rescan` 或找不到报告才重扫全树。**代价差 100 倍以上**：

| 路径 | 耗时 |
|---|---|
| 复用审计 CSV | < 1 s（只读 CSV） + 逐个反演 |

### 6.2 `--limit` 与"截断"标注

`audit` / `convert-all` / `plot-all` 都支持 `--limit`。截断运行时，
报告头部**必须**显式标注：

```python
extra=[("声明文件总数", n_declared),
       ("本次审计样本", f"{total}" + ("（**截断**）" if limit else "（全量）"))]
```

★ 为什么这个标注是硬要求：截断后的闸口等式
`992 + 222 == 1214` 会变成 `40 + 0 == 40`（也成立），
**读者会把截断结果当全量结论**。标注是防止误读的唯一手段。
