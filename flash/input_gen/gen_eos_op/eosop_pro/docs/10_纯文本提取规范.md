# 10 · 纯文本提取规范

> **用户的要求**：*"需要特别注意纯文本数据的提取方式。"*

这篇是**可执行的规范**：任何人在 `matter++` 里加一个新格式，照着做就对了。
每一条都附实测反例 —— 这些反例全是真踩过的。

---

## 0. 总纪律（三条，先记住）

| # | 纪律 | 违反的后果 |
|---|---|---|
| 1 | **L1 定宽是首选，L2 正则是兜底**；两条路径在同一文件上必须给相同结果 | 打包负号被 `split()` 吞掉 |
| 2 | **`extract_numbers()` 只作用于已剥离表头的 payload** | 注释里的 `#3711 DATED: 22581` 变成数据 |
| 3 | **表头一律走 L2 正则，绝不定宽切片** | `'2.70000000e+00 1'` → `ValueError` |

## 1. 字节层：先决定"能不能当文本读"

### 1.1 采样而非全量

```python
SAMPLE_BYTES = 256 * 1024     # 256 KiB 足以判定
```

理由：目录总大小 695.9 MiB，其中 `ATOMIC/*.txt` 单文件 13.5 MB。
为判定编码而全量读取会让 `inventory` 从 6 s 涨到分钟级。

### 1.2 编码链（顺序即语义）

```python
ENCODINGS = ("utf-8-sig", "utf-8", "gb18030", "latin-1")
```

顺序不可交换：

| 位置 | 编码 | 为什么在这个位置 |
|---|---|---|
| 1 | `utf-8-sig` | **26 个文件带 BOM**（实测全部是 `.log/.txt/.md/.xml`，数据表 0 个）。放第一位才能顺带剥 BOM |
| 2 | `utf-8` | 绝大多数文件 |
| 3 | `gb18030` | `matter++/Readme.txt` 是 **GB18030 中文**，`utf-8` 会抛 `UnicodeDecodeError` |
| 4 | `latin-1` | **永不失败**的兜底（任何字节序列都是合法 latin-1） |

`encoding_chain(data)` 在**带 BOM 时**会调整顺序（BOM 是强信号）。

### 1.3 NUL 一票否决

```python
NUL_BYTE = b"\x00"
```

实测 **1 个**文件含 NUL 字节：`XrayMassCoef/.../Thumbs.db`。
含 NUL 的字节流不可能是有意义的定宽 ASCII 表，所以直接转 `skipped_non_numeric`，
**不进入解析路径**。

### 1.4 行尾风格

实测分布（`inventory` 报告）：**CRLF 997 / LF 154 / 混合 3**。

★ 三个"混合"文件就是最危险的情况：
如果按 `"\n"` 切行，`\r` 会留在行尾，最后一个字段变成 `"3.14\r"`。
所以读行必须**同时**处理：

```python
text.replace("\r\n", "\n").replace("\r", "\n")
```

`config` 里 `BOM = "\ufeff"`，`textio.strip_bom()` 无条件剥离
（26 个带 BOM 的文件全部是文档类，剥掉无风险）。

## 2. L1 定宽切分（首选路径）

### 2.1 实测的字段宽度与每行字段数

| 族 | 字段宽 | 每行字段数 | 依据 |
|---|---|---|---|
| MULTI / SESAME（F1、F2） | **15** | **4** | `matter++/Readme.txt` |
| Hyades（F3） | **15** | **5** | `doc/Hyades 数据格式说明.doc` |
| MPQeos（`.301/.304/.305`） | **16** | **4** | `matter++/Readme.txt` |

```python
WIDTH_MULTI   = 15
WIDTH_MPQEOS  = 16
FIELDS_MULTI  = 4
FIELDS_HYADES = 5
PLAUSIBLE_WIDTHS = (15, 16)     # 允许的宽度集合（交叉校验用）
```

### 2.2 为什么定宽是首选

打包负号是**定宽**的直接后果：

```
-0.60000000E+01-0.55789474E+01-0.51578947E+01-0.47368421E+01
```

这是 4 个数（每个 15 字符），负数吃掉前导空格 → 字段紧邻、无分隔符。
**按 15 切一定正确**，而 `str.split()` 只得到 1 个 token。

```python
def slice_fields(line, width=WIDTH_MULTI, n_fields=None) -> list[str]:
    """按定宽切出字段文本（不做数值转换）。"""

def slice_values(line, width=WIDTH_MULTI) -> list[float]:
    """按定宽切 + 解析成 float。"""
```

### 2.3 字段宽度**不是全局常量**

同一族内会变：

| 文件 | 实测 `W` |
|---|---|
| `mat_Al-1.0/FEOS/Al.feos.301` | **15** |
| `mat_Au-1.0/Au.301` | **16** |

所以宽度必须**逐文件推断**：

```python
def infer_payload_width(lines) -> tuple[int, str]:
    """返回 (W, 判据说明)。

    优先：len(line) // n_fields（"满行语义"下精确）
    候选：PLAUSIBLE_WIDTHS 里能整除行长的那一个
    """
```

判据字符串会写进 `layout_rule`，例如
`"F4/MPQeos: 4 + nr + nt + 3*nr*nt (W=15)"`。
**"我按 15 还是 16 切的"永远可回溯。**

## 3. L2 数值正则（兜底 + 表头）

### 3.1 一个正则吃下全部实测写法

```python
FORTRAN_NUM_RE = re.compile(
    r"[+-]?(?:\d+\.\d*|\.\d+|\d+)(?:[EeDd][+-]?\d+)?")
```

必须覆盖的写法（**全部在 `matter++` 实测到**）：

| 写法 | 出处 | 说明 |
|---|---|---|
| `.27000000E+01` | `AL_eos` | Ramis 无前导零 |
| `1.1041000e+004` | `1041_PLANCK` | **小写 `e` + 三位指数** |
| `-0.60000000E+01` | `AU_op03z` | 紧邻负数 |
| `1.` | `AU_SIMPLE_PLANCK_MG` | 空小数 |
| `.0` | `AL_IDEAL_GAS` | 无整数部分 |
| `5.00000000E+01` | `eos_41.dat` | 纯 Fortran E 格式 |
| `1.0D+03` | 老式 Fortran 表 | **`D` 指数** |

★ 三条容易漏：

1. **大小写 `E`**：F2 族内 `e` 与 `E` 混用（`1041_ROSS` 用小写、`AU_SIMPLE_*` 用大写）。
2. **`D` 指数**：老式 Fortran 的 double 写法，`float()` 认不了，要先换成 `E`。
3. **三位指数 `e+004`**：`float("1.1041000e+004")` 其实能解析，
   但正则里的 `[+-]?\d+` 必须**不限位数**，否则匹配会被截断。

### 3.2 MSVC 的 `-1.#INF0000e+000`

Windows MSVC 运行时把 `inf` 写成 `-1.#INF0000e+000`。
这个串**不匹配** `FORTRAN_NUM_RE`，会成为"残渣"，
把该行从"纯数值行"误判成"带字母的头部行"。

```python
SPECIAL_FLOAT_RE = re.compile(r"[+-]?1\.#(?:INF|IND|QNAN)[0-9a-fA-F]*")
_ITER_RE = re.compile("(?:" + SPECIAL_FLOAT_RE.pattern + ")|(?:"
                      + FORTRAN_NUM_RE.pattern + ")", re.I)
```

解析策略：映射到 `inf` / `nan`，并**在 `notes` 里标记为上游数据缺陷**：

```python
table.notes.append("⚠️ 上游数据缺陷：出现 MSVC 专有非有限值表示 "
                   "-1.#INF0000e+000（已按 inf 处理）")
```

★ **不静默丢弃**：`inf` 是数据里有的事实，丢掉才是失真。

## 4. `has_letters` / `numeric_coverage`：两个用错的判据

### 4.1 ❌ naive "含字母 → 是表头"

payload 行含指数 `E`，所以"含字母"会把**每一行 payload 都判成表头**。
第一版实现就是这样，导致所有文件的 header 行数 = 行数。

**修法**：先剔除数值 token，再看残渣里有没有字母。

```python
def non_numeric_residue(line: str) -> str:
    """把每个数值 token 替换成空格，返回剩下的"残渣"。"""

def has_letters(line: str) -> bool:
    """★ 必须**先剔除数值 token** 再判 —— 否则会误报（实测教训）。"""
    return _ALPHA_RE.search(non_numeric_residue(line)) is not None
```

### 4.2 ❌ naive "覆盖率低 → 是表头"

注释行也含数字：

```
ALUMINUM  LANL SESAME #3711 DATED: 22581 11483
```

它的 `numeric_coverage` 实测 **0.359**，不是 0。所以阈值判断会被注释行骗过。

**修法**：把"字母残留率"作为**主判据**，覆盖率只作辅助。

```python
def is_payload_line(line: str, *, coverage_min: float = 0.99) -> bool:
    """payload 行 = 无字母残留 **且** 数值覆盖率达标。"""
    return (not has_letters(line)) and numeric_coverage(line) >= coverage_min
```

两个条件的**与**关系很关键：
- 只有 `not has_letters`：空行会被判成 payload
- 只有 `coverage`：注释行会被判成 payload

### 4.3 模态滤波：区分"偶发异常"与"结构性中断"

```python
payload_flags         # 模态滤波后的 payload 标记（用于定位 header/payload 分界）
payload_flags_raw     # 未滤波（用于**检测中断**）
```

`payload_flags_raw` 的用途：一个中途插入的"带字母行"可能是
**多块拼接的分隔**（如 `AU_eosd` 的 2 块之间），也可能只是脏行。
保留未滤波版本才能在需要时把两者分开。

## 5. 列剖面：宽度推断的两条路径

```python
def profile_columns(lines) -> ColumnProfile
```

算法：

1. 对 payload 区逐行收集"非空白字符出现过的列位"
2. **恒为空白的列**是天然的字段边界 → 位置序列的间距**众数**即字段宽 `W`
3. 用 `W × 每行字段数 ≈ 行长` 交叉校验

### 5.1 退化情形（很常见）

负号吃掉前导空格后**没有任何空白列**，空白列法失效。

```
-0.60000000E+01-0.55789474E+01-0.51578947E+01-0.47368421E+01
```

此时退化为：

| 方法 | 公式 | 可靠性 |
|---|---|---|
| **长度法（主）** | `W = len(line) // tokens_per_line` | **首选**，满行语义下精确 |
| 空白列法 | 空白列间距众数 | 不可靠（右对齐字段会干扰） |
| L2 计数 | `W = len(line) // count_tokens(line)` | 兜底 |

★ 最初用空白列法（`W_gap`），在右对齐字段上给出错值。
改成**长度法为主**后稳定。`ColumnProfile` 同时给出两条路径的结果与所用判据，
**让人能看出结论是怎么来的** —— 这就是"报告即证据"在函数层的体现。

实测输出（`AL_eos`）：

```
列剖面: rows=2494 max_len=60 blank_cols=4 W_gap=15 W_len=15 -> W=15
        （line-length // tokens-per-line，满行语义下精确）
```

## 6. 注释行剥离：八种写法

`generic_curve` 与各专门解析器都要剥离注释，实测到的注释前缀：

| 前缀 | 出处 |
|---|---|
| `#` | `hugoniot`、`ColdOpacity`、`HOP` 注释 |
| `%` | FEOS 参数文件（PDF §4 逐字） |
| `c` | `hyades/coldopac.dat`、老式 Fortran 注释 |
| `C` | 同上（大写） |
| `REM` | `material.base` |
| `!` | Fortran 90 |
| `*` | 老式 Fortran |
| 纯文本行（无前缀） | 第 0 行材料名（`ALUMINUM  LANL SESAME …`） |

★ `c` / `C` 前缀**不能无脑剥** —— 会伤到以 `c` 开头的英文数据行。
所以只在**行首且后跟空白或行尾**时才当注释：

```python
_COMMENT = ("%", "#", "!")
_COMMENT_WORD = re.compile(r"^\s*(?:c|C|rem|REM|\*)\s")   # 需要后面跟空白
```

## 7. 尾部与特殊字节

### 7.1 DOS EOF `\x1a`

```python
DOS_EOF = "\x1a"
```

`hyades/sesame/eos_*.dat` 末行可能有它。不处理则最后一个字段变成
`"1.234E+00\x1a"` → `float()` 失败。

处置：**剥离 + 登记**（`notes` 里写"含 DOS EOF 标记 \x1a（已忽略，不参与数值）"）。

### 7.2 尾部补零

F3 族实测有"凑满每行 5 字段"的填充。处置原则：

1. **原样保留**成独立字段 `raw_tail`，单位标 `unknown`
2. `expected = 公式值 + len(tail)`，**否则会误报 `count_mismatch`**
3. `notes` 里写明"⚠️ 数组末尾有 N 个补零（实测为该族凑满每行 N 字段的填充）"

### 7.3 空行

`blank_line_indices` 单独记录，**不参与 payload 计数**，但保留位置信息
（`TextDoc.blank_line_indices`）。用途：多块拼接检测时，空行是天然的块分隔候选。

## 8. 写出规范

| 项 | 规定 | 理由 |
|---|---|---|
| 换行 | 一律 `\n`（LF） | 脚本要在 WSL / 超算 Linux 上跑；CRLF 破坏 shebang |
| 编码 | UTF-8（报告用 `utf-8-sig` 便于 Excel 打开） | — |
| 数值格式 | 保持源文件宽度（`%15.7e` / `%14.7e`） | 跨格式转换时字段对齐 |
| 报告时间戳 | `%Y%m%dT%H%M%S` 本地时间 | 文件名按时间排序即按生成顺序 |
| 报告 UTC | `%Y-%m-%dT%H:%M:%SZ` | 便于跨时区对照 |

`reporting.write_csv` 用 `utf-8-sig`：Excel 双击打开中文列名不乱码。
`reporting.write_md` / `write_json` 用 `utf-8`。
