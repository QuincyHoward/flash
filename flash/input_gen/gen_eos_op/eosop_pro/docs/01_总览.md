# 01 · 项目总览

> **一句话**：把 `Multi1D++Portable20241128/matter++` 里 **6 大格式族、15 种解析器、1214 个文件**
> 的物质数据（EOS / 不透明度 / Z̄ / NLTE / 冷不透明度 / 雨贡纽…）统一解析、
> 统一网格化、统一落盘为 HDF5，并把每一步的判定依据写成可回溯的报告。
>
> **闸口**：`已解析 992 + 已跳过 222 == 1214`，**问题文件 0**，耗时 144.7 s。
> **交叉验证**：`identify` 比对 997 个文件 → `conflict` **0**。
> **下游**：`convert-all` 写出 **992 个 h5 / 335.3 MiB / 0 失败**。
> **测试**：**30 个测试文件 / 393 个测试全绿**。

## 1. 它解决什么问题

`matter++` 是一个**跨程序、跨三十年、多作者**积累的物性数据库：

| 来源程序 | 年代 | 数据形态 | 文件数 |
|---|---|---|---|
| **MULTI**（Ramis, MPQ） | 1985–2024 | 反演 EOS `(ρ,de)`；不透明度全 log10 | 391 + 41 |
| **Hyades**（Larsen, CAS） | 1990s– | 正表 EOS `(ρ,T)`；单群不透明度 | 99 + 36 |
| **SESAME / LANL** | 1980s– | 4×15 定宽 ASCII | 经由 F3 解析 |
| **FEOS / MPQeos**（JWGU） | 2012–2016 | 4×15 或 4×16；GPa / MJ·kg⁻¹ | 25 + 23 + 82 |
| **LEDCOP / ATOMIC**（LANL TOPS） | 2015– | 游离格式、多群、`keV` | 13 + 18 |
| **SNOP**（Tsakiris & Eidmann） | 1987– | 多群不透明度源头 | 12 |
| **Ionmix / 冷不透明度 / 雨贡纽 / 幂律** | 杂 | 各自小格式 | 17 + 67 + 4 + 104 |

痛点有四：

1. **单位陷阱**：同一个 `T` 字段，不透明度族是 **eV**，Z̄ 族是 **keV**，
   Hyades 是 **keV**，F1 的 T 是 **Kelvin**。差 3 个数量级的静默错误。
2. **定宽 + 打包负号**：`-0.6E+01-0.557E+01` 用 `split()` 只能得到 1 个数，实际是 2 个。
3. **文件名不可信**：`AL_eos.feos` 里装的**不是** FEOS 数据；`.301/.304/.305` 才是 MPQeos。
4. **无声明文件**：150 个文件没有扩展名，另有一批只有 `Readme` 级别的文字线索。

本项目的做法是：**先把"声明"和"内容"分成两段独立执行**（见 [02](02_两段式执行.md)），
声明解释不了的交给零先验结构反演，任何一步都不硬猜，任何结论都写进报告。

## 3. 模块地图（谁负责什么）

### 3.1 分层

| 层 | 模块 | 职责 | 不做什么 |
|---|---|---|---|
| **L1 字节** | `core/byteclass`, `core/textio`, `core/hashing` | 编码链、行尾、NUL、sha256 | 不懂格式 |
| **L2 数值** | `core/fortran_numbers`, `core/fixedwidth` | Fortran 数词法、打包负号、定宽切片 | 不懂字段语义 |
| **L3 结构** | `core/lineprofile`, `core/columnprofile`, `core/envelope` | 行/列剖面、物理包络 | 不懂家族 |
| **L4 家族** | `parsers/*` | 15 个解析器，各自 `parse()` → `ParsedTable` | 不做单位裁决 |
| **L5 裁决** | `registry/*` | 声明类型、材料合并、单位仲裁、Z̄ 盘点 | 不读 payload |
| **L6 反演** | `core/inference` | 零先验布局反演（阶段 B） | 不做家族判定 |
| **L7 产出** | `grid/*`, `writer/*`, `convert/*`, `plotting/*` | 统一网格、HDF5、跨格式、出图 | 不重新解析 |
| **L8 编排** | `batch.py`, `cli.py` | 批处理、报告、闸口 | 不含格式知识 |

### 3.2 关键"接口优先"设计

所有解析器都只产出一个 **`ParsedTable`**（`parsers/base.py`），
所有写出器都只消费一个 `ParsedTable`。于是：

```python
read(A)  →  ParsedTable  →  write(B)
```

**不需要**为每一对 (源格式, 目标格式) 写转换器 —— 新增一个目标格式 =
写一个 `write_x(table, path, **opts)` 并 `register(...)`。
这就是"为后期不同文件格式的相互转换留下接口"的落点，详见
[`convert/__init__.py`](../eosop_pro/convert/__init__.py) 与 [12_HDF5模式](12_HDF5模式.md)。

`ParsedTable` 的核心字段：

```python
table_key, kind, family, source_relpath      # 身份
table_id, sesame_digit, header_raw           # 溯源
axes: {"rho": [...], "Te": [...]}            # 自变量（物理量，非 log10）
axis_units, axis_log10                       # ★ 存的是 log10 还是物理量
fields: {"P": [...], "E": [...], "T": [...]}  # 因变量
field_shape, field_units, field_log10        # ★ 形状与对数标记
n_groups, group_bounds, unit_source, layout_rule
n_numbers_seen, n_numbers_expected, notes
```

## 8. 已知边界（诚实清单）

1. **`ok_unverified` 164 个**：结构（计数、单调性、包络）三项都过，但**没有声明单位**，
   用的是族默认值。若后续拿到说明书，应回到这些文件重判单位。
2. **多群段默认不解析**：`--multigroup` 才展开 LEDCOP 多群（体积/耗时都大）。
   13 个 `ledcop_atomic` 只解析了头 + 灰度段。
3. **PDF 文本层**：CID 字体的 PDF 抽不出文本（如实记 warning），
   Ramis 论文属此类，只能按页级元数据引用，不转述未读内容。
4. **`.xls`（BIFF8）**：用 UTF-16LE 游程扫描，不是结构化解析；
   表格结构会丢失，只保留文本内容。
5. **F1 的 `de` 基**：统一网格插值前必须先反演到 `(rho, Te)`（见 [13](13_统一网格与插值.md) §5），
   反演用线性插值，在 `de` 网格稀疏处误差会放大。
