# 02 · 两段式执行：声明优先，内容兜底

> **用户定的规矩**：*"文件类型识别的时候可以利用那些注释或者文字说明；
> 整个计划执行顺序是先单独文件后缀的数据提取与处理，所有文件处理完毕测试成功后再来搞文件识别。"*

本项目把这个规矩固化成**两个互相独立的阶段**，并且**顺序不可颠倒**：

```
阶段 A：按「声明」逐后缀提取        →  阶段 B：按「内容」零先验识别
（declarative）                        （content / inference）
─────────────────────────────          ─────────────────────────────
· 输入：扩展名 / 路径 / 文件名 /        · 输入：**只有字节流**
  注释 / 伴随文件 / 注册表              · 不读任何声明、不用任何先验
· 产出：ParsedTable（带单位与溯源）      · 产出：候选布局列表（含维度）
· 判定：家族由声明决定                  · 判定：维度由计数方程 + 单调性 + 包络决定
· 能力：能解 992/1214（81.7%）          · 能力：对任意文本给出 ok/ambiguous/unrecognized
· 闸口：已解析+已跳过 == 总数            · 闸口：不留未决项（候选全列）
```

**为什么必须 A 先于 B**：阶段 B 是"没有信息时的兜底"，如果 A 还没把能解的
都解完就去搞 B，会重复劳动，也无法判断 B 的准确率。

**为什么必须独立**：如果 A 里混入内容推断，就再也说不清"某条结论是因为声明、
还是因为你猜的"。分开之后，`identify` 子命令可以拿两边的结论做**交叉验证**
（见 §4）。

## 1. 阶段 A：声明通道

### 1.1 声明的六个来源（按可信度排序）

| 优先级 | 来源 | 例 | 实现 |
|---|---|---|---|
| 1 | **注册表引用** | `material.base` 的 `EOS mat_Au-1.0 AU_eos` | `registry/material_base.py` |
| 2 | **伴随注释文件** | `AU_info`、`Al.inhalt`、`#something` | `registry/annotation_store.py` |
| 3 | **路径 token** | `matter++/hyades/sesame/…` → Hyades 族 | `registry/declared_types.py` |
| 4 | **文件名 token** | `…/Al.GrayOpacity_ROSSELAND` → `ROSSELAND` | 同上 |
| 5 | **扩展名** | `.feos` / `.301` / `.coldopacity` | 同上 |
| 6 | **默认兜底** | 都没有 → 4×15 SESAME | 同上 |

### 1.2 权威依据（实测，非推测）

`matter++/Readme.txt` 是**上游自己写的分派规则**，逐字如下：

> 添加参数时请注意：文件名命名需要有如下的规则(不同格式有不同的单位转换)：
> 如果文件名和路径中有"hyades"，程序识别为hyades程序的文件
> 如果文件名和路径中有".feos"，程序识别为FEOS程序文件，按照一行4个15字符的数字读入
> 如果文件名和路径中有".301"或".304"或".305"，程序识别为MPQeos生成的每行4x16个字符
> 其他按照默认的SESAME数据库格式，每行4个15个字符。

摘录自 `docs/extracted/Readme__text__7a72a563.txt`（源：`matter++/Readme.txt`）。
这段文字**就是** `declared_types.declare()` 里 `default` 分支的实现依据 ——
不是我们发明的推断，是上游的契约。

### 1.3 声明的输出

```python
@dataclass
class DeclaredType:
    relpath: str
    families: list[str]      # ★ 候选列表，按顺序尝试
    kind: str | None
    source: str              # extension|path|name_token|registry|companion|default|skip_rule
    evidence: str            # ★ 判定依据的原文/模式，写进报告
    mid: int | None
    material: str | None
    sesame_id: int | None
    notes: list[str]

    @property
    def family(self): return self.families[0] if self.families else None
    @property
    def is_skipped(self): return self.family == "skip"
    @property
    def is_unresolved(self): return not self.families
```

**`families` 是列表而不是单值**，这是设计上的关键决定：声明只是**候选**，
真正用哪个解析器由内容决定（§4）。

### 1.4 声明来源分布（实测）

| dispatch_source | 文件数 | 占比 |
|---|---|---|
| `extension` | 405 | 33.4% |
| `path` | 348 | 28.7% |
| `skip_rule` | 217 | 17.9% |
| `name_token` | 137 | 11.3% |
| `default` | 107 | 8.8% |

注意 `default` 占 8.8%：**107 个文件完全没有声明线索**，只能按上游的
"其他 → 4×15 SESAME"规则猜。这批文件是阶段 B 的主要对象。
`skip_rule` 的 217 与最终 `skipped_non_numeric` 的 222 略有差异，
差额来自字节层二次判定（见 §2.2）。

## 2. 阶段 A 的解析与闸口

### 2.1 候选回退（candidate fallback）

`registry/dispatch.parse_declared()` 的行为：

```
for fam in declared.families:              # 按声明顺序
    parser = PARSERS[fam]
    try:  table = parser.parse(path, rel)
    except ParseError: continue            # 换下一个候选
    if table.count_ok: return table        # ★ 计数自洽才算成功
return last_resort(path, rel)              # 全部候选失败 → 最后的兜底
```

"最后的兜底"有两级：

1. **`generic_curve`**：把任何"两列数值"表当成 (x, y) 曲线收下（104 个文件走这条路）。
   这不是硬猜，而是**明确登记为低信息量**：`unit_source="generic"`，报告里单列。
2. **`skipped_non_numeric`**：字节层就判定不是数值表（NUL、非文本、Office 文档），
   登记跳过原因，**不算问题**。

### 2.2 字节层一票否决

在尝试任何解析器之前，先做字节层判定：

```python
bc = classify_file(path)
if bc.kind != "text":
    snap.status = "skipped_non_numeric"     # 例：Thumbs.db / *.xlsx / 长标题二进制
    snap.skipped_reason = f"byteclass: {bc.describe()}"
    return ParseOutcome([], snap)
```

编码链顺序是 `utf-8-sig → utf-8 → gb18030 → latin-1`（latin-1 永不失败）。
实测：**26 个文件带 BOM**，**12 个非 UTF-8**，`matter++/Readme.txt` 是 **GB18030 中文**。

### 2.3 闸口（Gate）

```
已解析(ok + ok_unverified) + 已跳过(skipped_non_numeric)  ==  审计样本数
```

并且 `error` / `count_mismatch` / `unrecognized` / `ambiguous_layout` /
`type_conflict` / `binary_suspect` 六类问题清单**必须为空或可逐条定性**。

实测（全量 1214）：

| 项 | 值 |
|---|---|
| `ok` | 828 |
| `ok_unverified` | 164 |
| `skipped_non_numeric` | 222 |
| **合计** | **1214** ✅ |
| 问题文件 | **0** |
| 耗时 | 115.9 s |

`ok` 与 `ok_unverified` 的区别只在**单位是否有声明**：

| 状态 | 含义 |
|---|---|
| `ok` | 结构自洽 **且** 单位有明确来源（伴随文件 / 内联声明） |
| `ok_unverified` | 结构自洽，但单位用的是**族默认值**，没有针对性声明 |

把这两者分开计数，是为了让"哪里还缺证据"一眼可见，而不是混成一个 992。

### 2.4 状态机全貌

```
                    ┌──────────────────┐
  文件 ─────────────▶│ 字节层 classify  │
                    └────────┬─────────┘
                             │
              ┌──────────────┴──────────────┐
              │ 非文本 / 含 NUL              │ 文本
              ▼                             ▼
      skipped_non_numeric          ┌───────────────┐
      (222)                        │ 声明 declare  │

                     skip│          无候选 │         有候选 │
                          ▼                ▼                ▼
                  skipped_non_numeric  unrecognized   ┌──────────────┐
                  (计入 222)             (0)          │ 候选回退解析  │
                                                      └──────┬───────┘
                                    ┌────────────────────────┼─────────┐
                              计数自洽 │              计数不符 │   全失败 │
                                    ▼                        ▼         ▼
                            ┌───────────────┐        count_mismatch  last_resort
                            │ 单位有声明？   │            (0)       (generic_curve)

```

## 3. 阶段 B：内容通道（零先验反演）

### 3.1 输入是什么

**只有**：
- 定宽切片后的行剖面 `LineProfile`（每行长度众数、表头行数、payload 行占比）
- 列剖面 `ColumnProfile`（字段宽度、空白列间隙）
- 表头里那几个整数
- payload 的数值总数

**不用**：扩展名、路径、文件名、伴随文件、任何注册表。

### 3.2 怎么反演

核心思路是**把表头整数当成未知数，解计数方程**：

```python
# core/inference.py
TEMPLATES = {                       # 8 个布局模板
  "f2_gray":     segs = [1, 1, d1*d2],              # rho, T, V
  "f2_mg":       segs = [1, 1] + ng * [1, 1, d1*d2],
  "f1_with_e0":  segs = [1, d1, d1, d2, d1*d2, d1*d2],   # rho, de, e0, P, T
  "f1_no_e0":    segs = [1, d1, d2, d1*d2, d1*d2],
  "hyades_eos":  segs = [2, d1, d2, d1*d2, d1*d2],        # L 已含 2
  "mpqeos":      segs = [1, d1, d2, d1*d2, d1*d2, d1*d2],
  "grids_only":  segs = [1, d1, d2],
  "ledcop_split":segs = [1, 1, d1*d2],
}
```

对每个模板、每个 `(d1, d2)` 候选、每个 `k`（前导表头行数），检查：

| 检查 | 含义 |
|---|---|
| **计数等式** | `sum(segs) == len(payload_values)`（含前导 k 行） |
| **单调性** | 网格段（rho / T / de）必须严格单调 |
| **物理包络** | 网格段与依赖段都要落在 `config` 的物理范围内 |

三关都过 → 进候选池。结论分三态：

| status | 含义 | 处置 |
|---|---|---|
| `ok` | 只解出**一个**自洽解 | 直接采用 |
| `ambiguous` | 有多个自洽解 | **全部列出**（含维度、score、容忍度），不挑一个 |
| `unrecognized` | 一个都没有 | 如实报告，附行/列剖面作为诊断材料 |

### 3.3 实测：F1 反演的"容忍度"表达

对 `mat_Al-1.0/AL_eos`（无任何提示）：

```
=== 通用布局反演报告 ===
状态: ok
行剖面: lines=2495 blank=0 modal_len=60 header=0 payload=2494 header_end=0
列剖面: rows=2494 max_len=60 blank_cols=4 W_gap=15 W_len=15 -> W=15
                （line-length // tokens-per-line，满行语义下精确）
表头数值: [37181000.0, 2.7, 66.0, 74.0]
维度候选: [(66, 74)]
payload 数值个数: 0
自洽候选 (1):
  - f1_with_e0(d1=66,d2=74,ng=1) payload=9974 mono=True env=True score=2.00
      · 前导表头行数 k=1
  ! k=1: dims=[(66, 74)] values=9974
  ! k=2: dims=[(66, 74)] values=9970
  ! k=3: dims=[(66, 74)] values=9966
```

三行 `!` 是**容忍度说明**：k=1 严格相等（9974），k=2/3 会差 4/8 个数。
选 k=1 不是"猜"，而是因为只有它严格自洽。误差量被显式写出来供人复核。

### 3.4 阶段 B 的收口

`infer-unknown` 不带参数时，对**阶段 A 判为未决**的文件批量反演。

★ 关键工程决定：**复用阶段 A 的审计 CSV**，而不是重扫全树。

```python
UNRESOLVED_STATUSES = ("unrecognized", "ambiguous_layout", "error", "count_mismatch")
targets = batch._problem_relpaths_from_report(latest_audit_report())
```

理由：全树重解析要 ~115 s，而 `audit_all.*.csv` 里 `status` 列已经写清了答案。
只有 `--rescan` 或找不到报告时才真的重扫。这与"结论要可回溯"是同一件事：
**报告不是副产品，是可以被程序消费的证据**。

## 4. 交叉验证：`identify`

两阶段都跑完之后，`identify` 子命令做**声明 vs 内容**的逐文件比对：

```python
@dataclass
class TypeComparison:
    relpath: str
    declared_first: str | None            # 声明候选的第一位
    declared_families: list[str]          # ★ 全部候选
    inferred_family: str | None           # 内容反演出的族
    inferred_template: str | None         # 命中的布局模板名
    inferred_dims: tuple[int, int] | None # 反演出的维度
    inference_status: str                 # ok | ambiguous | unrecognized
    agreement: str
    notes: list[str]
```

`agreement` 取值与判定条件（**顺序即优先级**）：

| 判定顺序 | agreement | 条件 | 含义 |
|---|---|---|---|
| 1 | `agree` | 反演族 == 第一候选 | 声明与内容一致 |
| 2 | `agree_structure` | 反演族与**第一候选**结构等价 | ★ 同一条计数公式、仅字段语义不同，反演无法区分 → **不是缺陷** |
| 3 | `order_mismatch` | 反演族 ∈ 候选但 ≠ 第一、且不同构 | ★ 声明优先级被内容推翻（候选回退救回来了） |
| 4 | `conflict` | 反演族 ∉ 候选列表 | 路径/命名规则被内容**否定** |
| 5 | `declared_only` | 反演无结论（`ambiguous`/`unrecognized`） | **不计为冲突** —— 很多结构本就超出扁平模板的表达力 |
| 6 | `inferred_only` | 无反演结论且声明也无候选 | 两头都没结论 |

### 4.1 为什么要单独的 `agree_structure`

`hyades_eos` 与 `hyades_opacity` **共用同一条计数公式**
`L = 2 + nr + nt + 2·nr·nt`（上游文档：不透明度"使用同样的格式，
压强处为平均 Rosseland 值，比内能处为平均 Planck 值"）。
反演只看结构，**无法**区分它们，于是 37 个 `hyades/Opacity/opc_*.dat`
会被报成 `order_mismatch`。

但它们**没有任何问题**：声明说"这是不透明度"（对），
反演说"这是 Hyades 布局"（也对）。把 37 条记成 mismatch 只会**淹没真正的
10 条 `conflict`**。所以显式声明"结构等价组"：

```python
STRUCT_EQUIV = (frozenset({"hyades_eos", "hyades_opacity"}),)
```

★ 这个"结构等价组"**不是**给不一致开脱的借口 ——
`test_struct_equiv_groups_share_a_count_formula` 用
`parsers.base.PAYLOAD_LAYOUTS` 交叉验证：组内家族的计数公式在多个
`(nr,nt,ng)` 组合上必须**逐值相等**，否则测试失败。

### 4.2 `order_mismatch` 是"信号"，不是"错误"

`order_mismatch` 恰恰说明**候选回退机制在起作用**：
声明的第一候选错了，但正确的族在候选列表里，于是解析成功了。
实测两例：

| 文件 | 声明第一候选 | 内容反演 | 结果 |
|---|---|---|---|
| `mat_Al-1.0/AL_eos.feos` | `feos_native`（因 `.feos`） | `multi_inverted_eos(f1_with_e0,(66,74))` | `order_mismatch`，**解析成功** |
| `Thermos/mat_Mo/Mo_Ideal_Gas` | `multi_opacity`（因 `Thermos/` 路径） | `multi_inverted_eos(f1_with_e0,(2,2))` | `order_mismatch`，**解析成功** |

如果候选列表只放一个族，这两个文件都会变成 `count_mismatch`。
**这就是"声明给列表而不是单值"的价值。**

### 4.3 ★ 交叉验证的实际产出：修掉 4 处分派错误

第一次全量 `identify` 跑出 10 条 `conflict` + 37 条 `order_mismatch`。
逐条查证后，**修掉了 4 处真实的分派错误**（详见 [20_格式规格与物理量单位手册.md](20_格式规格与物理量单位手册.md) §2 §3）：

| 错误 | 根因 | 修复 |
|---|---|---|
| `mat_CPC/{AU,BE}.INV` 被判 `feos_aux` | 名字 token 里有 `\|\.INV$`；`.INV` 其实是 MULTI **Inverted** EOS | 新增 `EXT_MAP[".inv"] → multi_inverted_eos`，进 `EXT_SPECIFIC` |
| 6 个 `.sesame` 退化成 `generic_curve` | `EXT_MAP[".sesame"]` 第一候选是无解析器的 `sesame_dat` | 改为 `("multi_inverted_eos", "sesame_dat", …)` |
| `Thermos/{Mo,U,W}_*Ideal*Gas` 被判不透明度 | `Thermos/` 路径规则只给 `["multi_opacity"]` | 加 `multi_inverted_eos` 为第 2 候选 |
| `PowerLawTa2O5_EOS.SESAME_` 被判 `generic_curve` | 尾部 `_` 让 `.sesame` 失配，名字 token `powerlaw` 抢到 | `_ext_of` 剥掉尾部下划线 |

**修复后 10 条 `conflict` 全部消除**，且全部解析为 `multi_inverted_eos` +
`status=ok`（见 `test_the_four_dispatch_fixes_end_to_end`）。

★ 这就是[两段式](#)的核心价值：**声明通道的覆盖率是 81.7%，
但它的正确率只有靠内容通道才能验证**。

## 5. 为什么两段式优于"一个聪明的自动识别器"

| 维度 | 单阶段（自动识别） | 两段式（本项目） |
|---|---|---|
| 可解释性 | "模型觉得是 F2" | "声明来自 `material.base` 第 312 行；内容计数自洽" |
| 覆盖率可核 | 只能报"识别成功 N 个" | 闸口等式 `992+222==1214` 可独立验算 |
| 单位 | 混在识别里，错了不知道 | 独立仲裁链，`unit_source` 逐文件记录 |
| 回归 | 改了识别器无法定位影响面 | 两阶段各自有测试，A 的结论作为 B 的输入是文件（CSV） |
| 未决项 | 悄悄降级 | 三态明确，`ambiguous` 强制列全候选 |

**代价**：阶段 A 的 `default` 分支（107 文件）和 `generic_curve`（104 文件）
是"低信息量结论"，需要人复核。这个代价被显式记账（`ok_unverified` 计数、
`generic_curve` 单列），而不是藏起来。
