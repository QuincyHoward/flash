# 13 · 统一网格与插值

> **用户的要求**：*"额外一套统一 (rho, T_e[eV])、(nele, T_e[eV])、(nion, T_e[eV]) 网格插值"*，
> 并明确 *"(nion, Te) 和 (rho, Te) 先做，(nele, Te) 后补"*。

本轮实现 **2 套**，接口按"x 轴变换函数"参数化，第 3 套加进来不需要改 writer / interpolate。

---

## 1. 三套网格的定义

| `gid` | x 轴 | 换算 | 状态 |
|---|---|---|---|
| `rho_Te` | `rho [g/cm³]` | — （原生即 x） | ✅ 本轮 |
| `nion_Te` | `n_ion [1/cm³]` | `n_ion = ρ · N_A / Ā` | ✅ 本轮 |
| `nele_Te` | `n_ele [1/cm³]` | `n_ele = ρ · Z̄(ρ,T) · N_A / Ā` | ⏳ 后补 |

★ 关键差别：`nion_Te` 是**纯换算**（`ρ ↔ n_ion` 一一映射），
而 `nele_Te` 需要 `Z̄(ρ,T)` 这个**二维场**，所以是**耦合变换**
（在每个 `Te` 列上对 `ρ` 做一维反演）。这就是为什么它单独拎出来后补。

```python
GRID_IDS = ("rho_Te", "nion_Te")   # 本轮；nele_Te 为后补预留
```

### 1.1 x 轴变换的参数化

```python
def x_from_rho(gid: str, rho: float, A: float | None) -> float:
    if gid == "rho_Te":
        return rho
    if gid == "nion_Te":
        return rho * config.N_A / A            # A 单位 amu → 近似 g/mol
    raise KeyError(gid)

def rho_from_x(gid: str, x: float, A: float | None) -> float:
    """逆变换。nion_Te 需要它来做"源 x 对齐"。"""
```

★ `A` 来自 `material.base`（`MaterialRegistry.for_file()` → `record.A`），
实测 `mat_Al-1.0/AL_eos` 得到 `A_amu = 26.982`。
`A is None` 时 `nion_Te` 轨**跳过**（并记 warning），不猜一个默认原子量。

### 1.2 新增 `nele_Te` 要改什么

只需加一对函数 + 一个 `GRID_IDS` 条目：

```python
def x_from_rho(gid, rho, A, *, Zbar=None, Te=None):
    if gid == "nele_Te":
        return rho * Zbar * config.N_A / A     # 需要 (ρ,T) 处的 Z̄
```

`writer` / `interpolate` / `batch` **一行都不用改** ——
它们只通过 `x_from_rho` / `rho_from_x` 两个函数与网格交互。
这就是 [12 §7](12_HDF5模式.md) 说的"接口优先"。

## 2. 网格构造

```python
def build_grid_for_tables(tables, *, gid, A=None, n_x=None, n_Te=None,
                          rho_range=None, Te_range=None, origin="") -> UnifiedGrid:
    """由一组表的原生范围（**取交集**）构造统一网格，并按物理包络裁剪。"""
    rng = data_ranges(tables)                  # 见下
    rho_range = _clip(rho_range[0], rho_range[1],
                      config.RHO_MIN_G_CM3, config.RHO_MAX_G_CM3)
    Te_range  = _clip(Te_range[0], Te_range[1],
                      config.TE_MIN_EV, config.TE_MAX_EV)
    return build_grid(gid, rho_range=..., Te_range=..., ...)
```

### 2.1 `data_ranges`：取交集，且过滤非正与非有限

```python
"""求一组表在 (rho, Te) 上的**交集**范围（忽略非有限与非正值）。"""
fin = [v for v in ax if v == v and v not in (inf, -inf) and v > 0]
```

★ **`v > 0` 这个条件不可省**：F1 的 `rho[0] == 0.0`（实测），
`log10(0) = -inf` 会让范围下界变成 `-inf`。

### 2.2 网格是 log10 等距

```python
rho_axis = make_log_uniform(lo_r, hi_r, n_x)   # 默认 n_x = n_Te = 128
Te_axis  = make_log_uniform(lo_t, hi_t, n_Te)
```

为什么是 log10 等距：物性数据在 log 空间的本征分辨率是均匀的
（EOS 表本来就是 log 网格），线性等距会在低密度端严重欠采样。

### 2.3 三套网格**共用同一条 Te 轴**

```python
"""三套网格**共用同一条 Te 轴**，只替换 x 轴变量。"""
```

好处：`rho_Te` 与 `nion_Te` 的同一 `(j, i)` 索引对应**同一个物理状态点**，
两张表可以直接逐元素比较（例如 `n_ion == rho·N_A/Ā` 的恒等式可当自检）。

### 2.4 网格元数据

```python
attrs = {
    "x_axis": x_axis,          # "rho" | "n_ion"
    "x_min": x_vals[0], "x_max": x_vals[-1], "n_x": n_x,
    "Te_min_eV": Te_axis[0], "Te_max_eV": Te_axis[-1], "n_Te": n_Te,
    "spacing": "log10",
    "nan_semantics": "out_of_range",
    "origin": origin or "tables-intersection",
    "A_amu": A,
}
```

`origin` 取值 `"tables-intersection"` 说明网格范围是**数据推出来的**，
不是配置里写死的 —— 这一点对可核验性很重要。

### 2.5 ★ 退化范围：宁可缺轨，不造假网格

```python
def can_build(range_) -> bool:
    """一个轴范围是否可用（正、有限、严格递增）。"""
    lo, hi = range_
    if not (math.isfinite(lo) and math.isfinite(hi)):
        return False
    return lo > 0 and hi > lo
```

**实测反例**：`Thermos/mat_Mo/Mo_Ideal_Gas` 的 rho 网格是 `[0.0, 1.0]`：

```
data_ranges 过滤 v > 0（因为 log10(0) = -inf 不可用）
  → 只剩 [1.0]
  → 范围退化成 (1.0, 1.0)
  → build_grid 抛 ValueError: invalid rho range: (1.0, 1.0)
  → ★ 整个 convert-all 在 700/1214 处**中断**
```

修法：`build_grid_for_tables` 在范围退化时返回 `None`，
`build_all_grids` 略过该 gid：

```python
def build_all_grids(tables, *, A=None, n_x=None, n_Te=None):
    out = {}
    for gid in GRID_IDS:
        g = build_grid_for_tables(tables, gid=gid, A=A, n_x=n_x, n_Te=n_Te)
        if g is not None:            # ★ 退化 → 略过，不抛异常
            out[gid] = g
    return out
```

后果：该文件的 h5 **少一条 unified 轨**（native 轨照写），
报告里记 `unified_skipped = "degenerate-range"`。

★ **为什么不"把范围撑开一点"**：那样造出来的网格在 `rho ∈ [1, 1]`
之外全是外插，写进 h5 就是**假数据**。宁可少一条轨，
让下游看见"这个表没有统一网格"，也不要让它以为有。

`--unified-only` 遇到退化文件时计入 `n_skipped` 并给出原因
`"unified-only 且轴范围退化 → 无轨可写"`，而不是写一个空 h5。

严格性只在**显式给坏参数**时保留 —— 直接调 `build_grid((1.0,1.0), …)`
仍然抛 `ValueError`（`test_build_grid_still_raises_on_direct_bad_input`）。

## 3. 插值实现

```python
"""二维重采样 —— 以 (log10 x, log10 Te) 为插值空间的双线性插值。

约定
----
* 源数组形状统一为 (n_Te, n_x)（与 ParsedTable.field_shape 一致）。
* 插值空间按量选择：x 用 log10，Te 用 log10；
  被插值的量：kappa 用 log10（本源数据即对数），P/E/Z 用线性。
* **越界 → NaN**（默认；可配 clamp / linear）。
* 返回 out_of_range 计数，写入 unified/<gid>/attrs。

实现用 numpy 的 np.interp 逐行/逐列做一维线性插值（等价于双线性），
越界由 left=right=nan 直接表达 —— 不需要额外掩码逻辑。
"""
```

### 3.1 为什么"逐行 `np.interp`"就是双线性

二维双线性插值可以分解为两步一维线性插值，
而"先在 x 方向逐 `Te` 行插值、再在 `Te` 方向逐 x 列插值"
与"先在 `Te` 方向、再在 x 方向"**结果相同**（双线性可交换）。
所以用 `np.interp` 循环两次就够了，不需要自己写网格搜索。

### 3.2 对数空间的三种组合

| 量 | x 空间 | y 空间 | 值空间 | 例 |
|---|---|---|---|---|
| F2 不透明度 | `log10` | `log10` | **`log10`** | `kappa`（源已是 log10） |
| F2 Z̄ | `log10` | `log10` | 线性 | `Z` |
| F1 EOS | `log10` | `log10` | 线性 | `P`、`E`、`T` |
| F3 EOS | `log10` | `log10` | 线性 | `P`、`E` |
| F4 MPQeos | `log10` | `log10` | 线性 | `P`、`E`、`Z` |

★ 三个"值空间"的选择都有物理理由：

- `kappa` 在 log 空间近似线性（幂律）→ 在 log 空间插值精度高得多
- `P`、`E` 在 log 空间也近似线性，但源数据是线性存的，
  所以**还原成物理量后仍在 log 空间插值**（`log_value` 参数控制）
- `Z` 是 `0..Z_max` 的有界量，log 空间在 `Z→0` 时炸掉 → 用线性

`log10_or_nan(arr)` 是辅助函数：对 `<= 0` 的元素返回 `NaN` 而不抛异常
（`np.log10` 对 0 会给 `-inf` 并打 warning，污染日志）。

```python
def log10_or_nan(arr):
    a = np.asarray(arr, dtype=float)
    out = np.full(a.shape, np.nan)
    m = a > 0
    out[m] = np.log10(a[m])
    return out
```

## 4. 单调性与重复点

```python
"""坐标轴单调性与重复点诊断 —— **默认不静默修复**。

约定
----
* 重复点判定用**相对容差** atol（默认 1e-12）。
* 非单调点/重复点一律**列出索引与数值** —— 写进 /meta/warnings 供人工判定。

```

| policy | 行为 | 何时用 |
|---|---|---|
| `error`（默认） | 抛异常 | 生产路径 |
| `average` | 重复点取平均 | 探索性；动作记入 `notes` |

## 5. ★ F1 的额外一步：`(rho, de) → (rho, Te)` 反演

这是全套统一网格里**最容易被忽略、后果最严重**的一步。

### 5.1 为什么必须反演

F1 的独立变量是 `(rho, de)` —— 密度与**比内能**。
统一网格的 x/y 是 `(rho, Te)`。**轴不一样，不能直接插值。**

```
F1 源:  P[de, rho]  T[de, rho]      轴 = (de, rho)
目标:   P[Te, x]                    轴 = (Te, x)

❌ 直接拿 T 当轴 → 数值全错（且形状可能恰好撞上，静默错位）
✅ 先对每个 rho 列反解 T→de，再取值
```

这正是上游文档描述的转换（`docs/extracted/MULTI使用的SESAME数据文件格式__ooxml-word__3e289d7f.txt`）：

> 对于 `P(R, E)`：对某个密度 R，首先根据 `E(R, T)` 找到对应的温度 `T(R, E)`，
> 这个过程需要差值；`P(R, E) = P(R, T(R, E))`，这里同样需要差值。

### 5.2 实现

```python
"""EOS 反演转换 —— 把 F1 的 (rho, de) 表转成 (rho, Te) 表。

算法（对每个密度列 j，共 nr 列）：
1. 取该列的温度序列 T[:, j]（随 de 单调升）；
2. 在 (log10 T, log10 de) 空间对目标 Te 做一维线性插值 → de*(Te)；
3. 在该 de* 上对 P[:, j] / E[:, j] 插值。
超出该列温度范围的目标点 → NaN（不静默外插）。
"""
```

关键点：

| 点 | 做法 | 理由 |
|---|---|---|
| 反解在 **`(log10 T, log10 de)`** 空间做 | 两端都是跨数量级的量 | 线性空间插值在低端严重失真 |
| **逐列**独立反解 | 每个 `rho` 列的 `T(de)` 曲线不同 | 不能共用一条曲线 |
| 越界 → **`NaN`** | 不外插 | 外插出的"温度对应的比能"没有物理依据 |
| 反演结果带 `origin="inverted-from-(rho,de)"` | 属性标记 | 让"这是算出来的"可追溯 |

### 5.3 写出时的两条轨

```python
def _write_unified_from_de_table(sub, table, g) -> int:
    res = to_Te_grid(table, list(g.Te), fields=("P", "E", "T"),
                     log_value=("T",))
    sub.create_dataset("x", data=np.asarray(g.x, dtype=float))
    sub.create_dataset("Te", data=np.asarray(g.Te, dtype=float))
    sub.create_dataset("rho_of_x", data=np.asarray(table.axes["rho"]))   # ★ 原生 rho 保留
    for nm, arr in res.fields.items():
        ds = sub.create_dataset(nm, data=arr, **_mk_kwargs(arr.shape))
        ds.attrs["origin"] = "inverted-from-(rho,de)"
        n_oor += int(np.isnan(arr).sum())
    sub.attrs["interp_method"] = "invert-(rho,de)->(rho,Te) + log10-bilinear"
```

★ `rho_of_x` 这一条是**刻意加的**：反演后的 `(rho, Te)` 网格里，
`rho` 轴就是源表的 `rho` 轴（未重采样），把它单独存一份，
使"这个场的 x 到底对应哪条 rho 序列"一目了然。

### 5.4 精度代价（诚实说明）

反演用**线性插值**，在 `de` 网格稀疏处误差会放大。`de` 网格是几何网格
（实测 `AL_eos`：74 点，相邻比值中位数 1.0851，范围 1.027–3.77），
在**高端**（比值接近 3.77）相对误差最大。

**本项目不掩饰这一点**：`out_of_range_count` 会统计越界点，
`coverage` 会给出有效占比。若某个表的 `coverage` 明显偏低，
报告里就能看到，而不是"看起来正常"。

## 6. 越界策略

```python
EXTRAPOLATION = _env("EXTRAPOLATION", "nan")     # nan | clamp | linear
```

| 策略 | 行为 | 适用 |
|---|---|---|
| **`nan`（默认）** | 越界写 NaN | 生产；与 `nan_semantics="out_of_range"` 一致 |
| `clamp` | 用最近的边界值 | 探索性；会让"外推"看起来像"真实数据"，**危险** |
| `linear` | 线性外推 | 探索性；同样危险 |

★ 默认必须是 `nan`。理由：
`clamp`/`linear` 会把"我们没有数据"伪装成"我们有数据"，
而下游无法分辨 —— 这与本项目"NaN 只表示越界、与 0 严格区分"的纪律一致。

两条探索性路径都是**显式选择**（环境变量或参数），不是默认行为。
