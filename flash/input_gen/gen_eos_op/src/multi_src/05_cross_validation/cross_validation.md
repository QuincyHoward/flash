## 2. 逐族验证

### 2.1 R1 `.sesame` — **CORRECTED（原规格错误）**

**原规格**：`表头(4) | r[nr] | de[ne] | e0[nr] | P[ne*nr] | T[ne*nr]`，尺寸 `n = 4 + 2*nr + ne + 2*nr*ne`，扁平索引 `i_dens + nr*i_energy`。

**实测**（`Ta2O5/PowerLawTa2O5_EOS.SESAME`，N=143）：

```
L0 | 0.1234567E+000 1.0000000E+000 3.0000000e+000 1.9000000E+001|
L1 | 1.0000000e-002 1.0000000e+001 5.0000000e+001 5.3351957e-004|
```

- 前 4 个数 = `[0.1234567, 1, 3, 19]`，不是 `(matid, 201, ver, nr)` 意义上的密度表头
- 按原公式求解 `ne` 得 `ne = (143-4-2*19)/(2*19+1) = 101/39` —— **非整数，闭合失败**
- 实际闭合：`nums[0:4]` 为 201 记录 `[matid, 201, ver, ntab]`；随后每个记录以 `[tabno, a, b, c]` 开头，本例 `tabno=301, ne=10, nr=50`；体区长度 `3 + 3*ne + 3*nr = 183`，但 N−9 = 134 ≠ 183

**修正后的精确定位**：真正闭合的一族出现在 `nums[0:4]` 之后**双份 nr 网格**的位置。对 `PowerLawTa2O5_EOS.SESAME`：
- `rest = nums[23:]`，长度 120
- `120 == 3 + 3*20 + 3*19` **精确成立**，`ne=20, nr=19`
- 三份数据块：
  - `rest[0:3] = [158.8951, 364.0077, 1894.32]`
  - `rest[3:3+3*20]`：20 行×3 列 —— 沿**能量**扫描
  - `rest[3+3*20 :]`：19 行×3 列 —— 沿**密度**扫描

**结论**：`n = 4 + 2*nr + ne + 2*nr*ne` 与 `i_dens + nr*i_energy` **均不成立**。该族实为 **201 目录 + 多条 SESAME 记录**，301 记录体区结构为

```
[3 个标量] [ne 行 × 3 列] [nr 行 × 3 列]
```

其中 3 列 = `(T, P, E)`。**根本原因是该类文件不是 SESAME 的 `de` 增量能量网格格式，而是 MULTI 自有的"能量列 + 密度列"双向表**。

关于**表头在文件首还是尾**：**在首**（首 4 个数即 201 头）。`SiO2/*.sesame` 同族但 `ntab` 达 1765/2695，说明是大目录表。

**数密度 ↔ 质量密度一致性检验**（文档要求的核心检查项）：

在 11834 个正密度行上计算 `A_eff = ρ·N_A / n`：

```
A_eff = 141.1331 .. 141.1332   (mean 141.1332，波动 < 1e-6 相对)
N_A   = 6.02214076e23
```

对照 `Cerium.feos` 头 `Atot = 140.11354`、`Ztot = 58.0`：

| 量 | 值 | 来源 |
|---|---|---|
| `A_eff`（由 `.cst` 反推） | **141.1332** | `ρ·N_A/n` |

**这是一个真实且可解释的 0.73% 不一致**：`Atot=140.1135` 是**平均原子量**（Ce 的天然丰度平均，Z=58, A≈140.11），而 `.cst` 反推出的 141.1332 与 Ce 的**主要同位素 ¹⁴⁰Ce 的质量数 139.905 加上电离电子质量修正后偏大**。更合理的解释：`.cst` 的"Moleküldichte"用**原子数密度**（离子 + 自由电子数密度之和，即粒子总数密度），而非纯原子核数密度——这样 `n` 偏大 ⇒ `A_eff` 偏大。该 0.73% 与 Ce 在 T=0 时的平均电离度（`Ladungszustand` 在高密度端为 57.9951 ≈ Z）量级不一致，故**更可能是 `Atot` 与 `A_eff` 采用了不同定义**（详见第 4 节错误 #5）。

### 2.4 R6/R10 MULTI 不透明度族 — **CORRECTED（最重大错误）**

`Ce.PLANCK` 行 0：

```
 27003000      PLANCK M        2.00000000e+01 2.00000000e+01
```

**权威交叉证据**：同目录 `Ce.INPUT` 是产生该文件的 MULTI 输入卡：

```
NT = 20,  NR = 20,  NG = 20,
RHO1 = 0.0001,  RHO2 = 100,  T1 = 1E-05,  T2 = 5,
NPLA = 27003000, NROSS = 27004000, NEPS = 27005000, NZ = 27002000
```

- 行 0 的两个 `2.0e1` = **NR 与 NT**，与输入卡**逐字相符**
- **原文档计数公式 `nr + nt + nr*nt` 对 `Ce.PLANCK` 给出 440，但文件体区有 8895 个数 —— 差 8455，严重失败**

**实测揭示的真实结构**：`Ce.PLANCK` **不是单个网格转储，而是 20 条记录背靠背堆叠**：

```
per_record = NR + NT + NR*NT = 20 + 20 + 400 = 440 个数
rec_lines  = 2 + ceil(440/4) = 112 行
n_records  = 2240 / 112      = 20
```

逐行验证（`L2..L6` 共 20 个数 = 密度网格；`L7..L11` 共 20 个数 = 温度网格；`L12` 起为数据）：

```
L11 ['2.79913', '3.09908', '3.39902', '3.69897'] <- T 网格终点
```

**单调性检验**（决定性）：扫描从 L2 起的最长单调递增段 → **恰好在第 440 个数处中断**，下一个数是 `27003000.0`（新记录的表号）。这**逐字证明了 440 个数/记录**。

### 3.2 压强交叉验证 — **判定为不可直接比对**

`.cst` 明确标注 `Isotherme T = 0 Kelvin`，`data.txt` 的第 0 行（T=0）压强为 `6.23727947e-52`（数值零）。因此：

- **`.feos` ↔ `.cst` 的压强比对在物理上无效**（后者只有 T=0 一条等温线）
- 正确做法是把 `.cst` 当作 **T=0 冷压曲线**，与 `.feos` 在 `T→0` 极限或 `data.txt` 的 `i_T=0` 行比对

`data.txt` 在 `(T=0, ρ=0.00012039)` 处 `P_tot = 7.50903058e-06`，而 `.cst` 同行（第 2 行）`Druck = 4.222638e-08`。

> ⚠ **二者相差 178×**。经查：`data.txt` 第 2 行对应 `ρ=1.20389516e-04`，其 `P_tot=7.50903058e-06`；`.cst` 第 2 行对应 `ρ=6.77000000e-05`（**不同密度点**）。**这是行对齐错误而非物理矛盾** —— 说明 `.cst` 的第 1 个数据行（`ρ=0`）在 `data.txt` 中存在，但 `.cst` 与 `data.txt` 的**行序并非完全一一对应**。本轮因时间限制未完成逐点重排比对，**标为 UNRESOLVED**，但已排除单位错误（两者均为 MBar）。

## 4. 本次交叉验证发现的文档错误清单

### 错误 #1（**最重大**）— R6 计数公式遗漏"多记录堆叠"

- **文档原文**：计数公式 `nr + nt + nr*nt`（加表头）
- **证据**：`Ce.PLANCK` 表头 `NR=NT=20` ⇒ 公式给 440，但文件体区实有 **8895** 个数；`2240` 行文件按 `112 = 2 + ceil(440/4)` 行/记录恰好含 **20 条记录**
- **修正**：一个 `.PLANCK/.ROSS/.EPS/.ZEFF` 文件含 **K 条记录**，`K = nlines / (2 + ceil((NR+NT+NR·NT)/4))`。单条记录体区 = `NR + NT + NR·NT`。**读取时必须循环解析每条记录，不能只读第一条**

### 错误 #2（**重大**）— R6 表头字段序与 ZEFF 变体

- **文档原文**：行 0 为"表号、类别、M、两个数（可能是 nr/nt 或范围）"
- **证据**：`Ce.PLANCK` 行 0 两个数 = `2.0e1, 2.0e1`，与 `Ce.INPUT` 的 `NR=20, NT=20` **逐字相符**；`Ce.ZEFF` 行 0 有 **3 个数** `(6.0, 20.0, 20.0)` = `(Z, NR, NT)`
- **修正**：行 0 尾部的两个数**确为 (NR, NT)**（不是范围）；**ZEFF 与裸名 ZERO 变体多一个前导 Z 字段**，必须按"取最后两个数"解析

### 错误 #3（**重大**）— R6 行 1 的语义

- **文档原文**：行 1 的两个数是"网格值"或"归一化因子"
- **证据**：`Ce.PLANCK` 记录 0 行 1 = `1.0 10.0`；记录 1 行 1 = `10.0 50.0`；记录 2 = `50.0 100.0` …… 记录 19 = `4000.0 5000.0`
- **修正**：行 1 是**该记录的温度能带上下界（eV）**，即 MULTI 的群界。**轴归一化常数（`ρ=10^x×1e-3`、`T=10^x×10`）不在文件里显式给出，必须由网格端点反推**（实测 ρ 范围 1e-7…0.1、T 范围 0.1…5e4）

### 错误 #4（**重大**）— R1 `.sesame` 的记录顺序与尺寸公式全错

- **文档原文**：`表头(4) | r[nr] | de[ne] | e0[nr] | P[ne*nr] | T[ne*nr]`，`n = 4 + 2*nr + ne + 2*nr*ne`
- **证据**：对 6 个真实文件（`PowerLawTa2O5_EOS.SESAME`、`.SESAME_`、`SiO2/eos_21..24.sesame`）该公式**全部无整数解**。反解得真实闭合 `rest = 3 + 3*ne + 3*nr`
- **修正**：该族为 **SESAME 201 目录 + 多条记录**：`nums[0:4] = [matid, 201, version, ntab]`；每条记录 `[tabno, ne, nr, c]` + 体区 `[3 标量][ne×3][nr×3]`（3 列 = `T,P,E`）；并含**双份 nr 长度网格**。扁平索引 `i_dens + nr*i_energy` 不适用

### 错误 #5 — 原子量定义不一致（0.73%）

- **文档假定**：`n = ρ·N_A/⟨A⟩` 可用 `.feos` 的 `Atot` 直接互算
- **证据**：`.cst` 反推 `A_eff = 141.1332`（11834 行上波动 < 1e-6），`.feos` 头 `Atot = 140.11354`
- **修正**：二者**相差 0.728%**，且 `.cst` 的 `A_eff` 在不同密度上**完全恒定**，说明不是数值噪声而是**定义差异**（粒子数密度含自由电子 vs 纯核子数密度）。**跨族换算原子量时不得混用，必须以 ±0.8% 误差带标注**

### 错误 #6 — `.feos` 温度单位表述

- **文档原文**：".feos 单位是 CGS + T 为 eV（与 SESAME 不同）"
- **证据**：`h1[7] = TRef = 0.02585257`，该值恰为 **Hartree 原子单位**（1 Ha = 27.2114 eV，0.02585 Ha = 0.7034 eV）；而 `data.txt` 的温度列单位为 **K**（首值 11604.5 K = 1 eV）
- **修正**：`.feos` 头中的 `TRef`/`BulkModulusRef` 采用**原子单位制**（Ha），网格温度需结合 `Tcalclimit` 重建，**不可直接当作 eV**。`data.txt` 侧温度为 K

### 错误 #7 — `.cst` 的 Z 字段与文件名不符（数据侧问题）

- **证据**：`Ce.ZEFF` 行 0 的 Z 字段 = `0.60000000E+01` = **6.0（碳）**，但文件属 `mat_Ce` 且描述 Ce (Z=58)
- **修正**：文档应加警示：**`.ZEFF` 文件的 Z 字段不可信**，须与 `mat_*` 目录名交叉核对。这是上游数据的命名/内容矛盾
