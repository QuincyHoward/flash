# 01 — 场景说明与拓扑

> SNBVTi = 仿 `TiTi2` 结构 + `shld` 由 Ti 改 V + `tar2` 保留 Ti + 其余 `tar*` 用 CH + SNB 模型。
> 最后更新：2026-09-13（NC-E 极短验证通过后）

---

## 1. 设计来源与派生关系

### 1.1 用户需求（原文）

> 仿照 `TiTi` 的结构和材料设置，**仅仅把 `shld` 的 Ti 层改为 V 层**，
> 然后**只仿真 2 µm 的情况**，其余深度使用 CH 材料表示 `tar*`，然后是 SNB 场景。

### 1.2 两条派生线索

| 维度 | 来源 | 继承内容 |
|---|---|---|
| **结构与材料** | `tracer/TiTi/TiTi2.py` | 12 区分层拓扑、`delta=0.1µm`、`L1..L6 = 1/2/3/4/6µm`、`D=50µm`、域 `[-0.04,0.01] cm`、8 物种、82 点激光脉冲、MGD 10 能群、全部 `tar*` 独立标记 |
| **驱动与物理** | `tracer/SNB/SNBOneCH_ml/SNBOneCH_ml.py` | FLASHSNB setup 标志、SNB par 覆写、`+ug` 网格策略、超算部署/提交/收集全套流水线 |

### 1.3 与两个母场景的差异矩阵

| | `SNBOneCH_ml` | **`SNBVTi`** | `TiTi2` |
|---|---|---|---|
| 热传导 | SNB | **SNB** | SH（标准） |
| `shld` | CH 1.0 | **V 6.11** | Ti 4.54 |
| `tar2` | CH 1.0 | **Ti 4.54** | Ti 4.54 |
| `tar1/3/4/6` | CH | **CH** | CH |
| 示踪深度 | — | **仅 2.0 µm** | 1 / 2 / 3 µm（三兄弟） |

> ★ 因此 SNBVTi 是**单变量对照的中间支点**：
> 与 `SNBOneCH_ml` 比 ⇒ 只变材料（CH→V, CH→Ti）；
> 与 `TiTi2` 比 ⇒ 只变热传导模型（SH→SNB）+ shld 材料（Ti→V）。

## 2. 分层拓扑详解

### 2.1 几何常量

| 符号 | 值 | 含义 |
|---|---|---|
| `xmin`, `xmax` | `-0.04`, `0.01` cm | 计算域（-400 … 100 µm） |
| `delta` | `0.1 µm` | **所有**薄层（shld + 6 个 tar）的公共厚度 |
| `L1` … `L6` | 1 / 2 / 3 / 4 / 6 µm | 各 `tar*` 层的**外边界**累积位置 |
| `D` | `50 µm` | 尾部 `samp` 厚度 |

### 2.2 12 区边界表达式

`Simulation_initBlock.F90` 中（全部为 **par 运行时参数**，改值即改几何、无需改代码）：

```
bnd1  = 0.0
bnd2  = sim_shldRadius                       →  V 层外边界
bnd3  = sim_tar1Radius                       →  tar1 外边界
bnd4  = sim_tar1Radius + sim_shldRadius      →  tar1 内边界
bnd5  = sim_tar2Radius
bnd6  = sim_tar2Radius + sim_shldRadius
bnd7  = sim_tar3Radius
bnd8  = sim_tar3Radius + sim_shldRadius
bnd9  = sim_tar4Radius
bnd10 = sim_tar4Radius + sim_shldRadius
bnd11 = sim_tar6Radius
bnd12 = sim_tar6Radius + sim_shldRadius
bnd13 = sim_tar6Radius + sim_shldRadius + sim_sampHeight
```

> ★★ **关键机制**：6 个 `tar*` 薄层的厚度由 `sim_shldRadius` **统一提供**
> （形如 `sim_tarXRadius + sim_shldRadius`）。这就是"薄层等厚"的来源，
> 也是为什么 `delta` 是全局单一参数。修改 `delta` 会**同时**改变 7 个薄层的厚度。

## 3. 为什么 `tar*` 全部保留独立物种标记

即使用同一张 CH 表、同一密度，`tar1/3/4/6` 仍各自是**独立物种**：

- **追踪需要**：诊断（烧蚀前沿 `x_a`、临界密度面 `x_c`、激波前沿 `x_s`）依赖
  "初始位于某深度的物质现在在哪里"。同物种合并后无法分深度追踪。
- **对照需要**：6 个标记层提供 6 个 Lagrangian 探针，可反演速度剖面。
- **成本**：仅多 4 个被动标量，无额外 EOS/辐射内存。

## 4. 材料表选择依据（IONMIX4 cn4 头部权威格式）

**权威来源**：`eos_tabReadIonmix4Tables.F90`。cn4 头部 4 行：

| 行 | 内容 |
|---|---|
| 0 | `nT nD`（**温度在前**！） |
| 1 | `atomic #s of gases` ← **成分判据** |
| 2 | `relative fractions` |
| 3 | `ngroupsEnergy` |

实测：

| 文件 | 行1（Z） | 判定 |
|---|---|---|
| `V-BADGER-TOPS.cn4` | `23` | ✓ 真钒表 |
| `Ti-BADGER-TOPS.cn4` | `22` | ✓ 真钛表 |
| `CH-QC-1-001.cn4` | `6, 1` | ✓ C:H |
| `He-BADGER-TOPS-Final.cn4` | `2` | ✓ He |
| ~~`CH-BADGER-TOPS-Final.cn4`~~ | `3` | ✗ **名实不符，禁用** |

> ⚠ 该文件名为 "CH" 但实际是 Z=3 的单元素表。赋给 CH 族物种会使
> IONMIX4 读取器报 `IONMIX4 file not found` 并拒绝加载。
> `SNBVTi.py` 的 `verify_generated()` 对此有**硬断言**，误用即中止。

## 5. 网格策略（`+ug` 均匀网格）

### 5.1 为什么必须 `+ug`

SNB 非局域热流的群分辨积分**跨多个电子平均自由程**。
AMR 的粗细块界面会制造人工梯度破缺点 ⇒ 必须均匀网格。

### 5.2 约束推导

```
dx = (xmax - xmin) / (iprocs · nxb)
```

要求 `dx ≤ 0.03 µm`（让 0.1 µm 薄层至少覆盖 3 个单元中心，
否则该物种**从不被写入** ⇒ 密度跳变 6 个数量级 ⇒ 立即崩溃）。

```
域宽 = 0.05 cm = 500 µm
需要 iprocs · nxb ≥ 500 / 0.03 = 16,667
取 nxb = 128, iprocs = 131 → dx = 500/(131·128) = 0.02982 µm ✓
```

> ★★ **`+ug` 下 `nproc` 必须严格等于 `iprocs`** ——
> `+ug` 只建 `iProcs` 个 level-1 块，par 里的 `nblockx` / `lrefine*` 被**无视**。
> 若 `mpiexec -n ≠ iprocs` → 块数不匹配 → 直接失败。
>
> ★ 实测核数推荐：**131 核最快**（0.288 s/step）；192 核慢 1.63×；
> 256 核因 `Negative 3T internal energy` 中止。

## 6. 自检清单（`verify_generated()` 覆盖）

`--generate-only` 后自动执行，全部通过才返回 0：

1. **材料绑定断言**：`sim_rhoShld` / `eos_shldTableFile` / `op_shldFileName` →
   V 三连；`sim_rhoTar2` / `eos_tar2TableFile` / `op_tar2FileName` → Ti 三连；
   `tar1/3/4/6` → CH 表
2. **浮点键数值断言**：`sim_rhoCham=1e-6`、`sim_rhoSamp=1.0`、`sim_rhoShld=6.11`、
   `sim_rhoTar2=4.54`、`diff_eleFlCoef=0.06`、`cfl=0.2`
   （★ 数值比较，避免 par 全精度写法 `1.000000000000000e-06` 导致字符串匹配误判）
3. **SNB 铁律**：`gr_hypreUseFloor=.false.`、`RiemannSolver=HLL`、
   `rt_useMGD=.true.`、`useDiffuse=.true.`、`iProcs`
4. **Config 编译期默认值断言**：`sim_rhoTar1/Tar3/Tar4/Tar6/Samp` = CH 1.0
   （这些键**有意不写进 par**，但 `Simulation_initBlock.F90` 会读 ⇒ 必须在 Config 正确）
5. **初值一致性**：8 物种 `sim_tele/tion/trad` 全部声明且相等
6. **cn4 成分核验**：逐表按行1 断言 Z
7. **网格自检**：`dx ≤ 0.03 µm` 且薄层单元数 ≥ 3

> ★ 第 4 项源于一个真实教训：par 里看不到的键最容易被忽略，
> 但它们由 Config 编译期默认值决定，错了会直接导致初始化密度/温度错误。
