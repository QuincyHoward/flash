## 4. ★★★ 委托复用机制（本场景的核心设计决策）

### 4.1 为什么委托而不复制

SNB 超算路径沉淀了大量实测踩坑（SFTP 不展开 `~`、`--skip-build` 需补 tar 解压、
运行前 `gr_hypreUseFloor` 闸门、cn4 远端兜底、HDF5 `LD_LIBRARY_PATH`、
build/probe/run 三作业编排、输出收集回退）。**复制一份必然漂移**。

故 `SNBVTi.run_hpc_pipeline()` 采取 **rebind + delegate**：

```python
from ...SNBOneCH_ml import SNBOneCH_ml as ref

# 0) ★ 先格式化 SETUP_FLAGS 的 {nxb} 占位符（见 §4.3）
_flags_ug, _nxb, _dx = build_setup_flags_ug(nproc, cfg["xmin"], cfg["xmax"])
_sg = _flags_ug

# 1) 重绑定命名常量
_bind = {"SIM_NAME":…, "OBJDIR":…, "BASENM":…, "PAR_FILENAME":…,
         "LOG_FILE":…, "INPUT_DIR":…, "OUTPUT_DIR":…, "SETUP_FLAGS": _sg}
saved = {k: getattr(ref, k) for k in _bind}
for k, v in _bind.items(): setattr(ref, k, v)

# 2) 委托
try:
    rc = ref.run_hpc(account=…, tmax=…, nproc=…, skip_build=…, …)
finally:
    for k, v in saved.items(): setattr(ref, k, v)   # 无条件恢复
```

### 4.2 ★★ 委托必须枚举被调函数的**全部**隐式依赖

首次委托时踩中**两类**漏网点（都已修复，详见 `../../SNB/docs/05_坑位清单.md` **P25**）：

| # | 漏网点 | 症状 | 修复 |
|---|---|---|---|
| ① | `run_hpc` **函数体内硬编码**材料表清单 `("He-…","CH-QC-…","CH-BADGER-…")` | `单元必需文件缺失: CH-BADGER-TOPS-Final.cn4`（V/Ti 表不在清单） | `SNBOneCH_ml.py` 改为 `sorted(INPUT_DIR.glob("*.cn4"))` 动态发现 |
| ② | 调用方 `main()` 里的**全局赋值副作用**：`globals()["SETUP_FLAGS"] = _flags_ug` | `ValueError: invalid literal for int() with base 10: '{nxb}'`，22 s 即 SETUP_FAIL | 委托层**自行**调 `build_setup_flags_ug()` 格式化 |

> ★★ **教训**：不能只检查"模块级命名常量"。
> 判据是**对 `run_hpc` 函数体做正则扫描**，列所有 `*.cn4` / `{...}` 占位符 /
> 场景名字面量，并核查调用方 `main()` 是否对全局做了隐式改写。

**排查片段**：

```python
import re
body = open(ref.__file__, encoding="utf-8").read()
i = body.find("def run_hpc("); j = body.find("\ndef ", i + 10)
seg = body[i:j]
for pat in (r"[\w-]+\.cn4", r"\{[a-z]+\}", r"SIM_NAME", r"OBJDIR", r"BASENM"):
    print(pat, re.findall(pat, seg))
for m in re.finditer(r'globals\(\)\["(\w+)"\]\s*=', body):
    print("main() 改写全局:", m.group(1))
```

### 4.3 `{nxb}` 占位符的两处消费点

`SETUP_FLAGS_UG` 是**模板**（含字面 `{nxb}`），只在两处被格式化：

| 路径 | 格式化位置 |
|---|---|
| 本地 WSL | `main()` → `globals()["SETUP_FLAGS"] = _flags_ug` |
| **超算委托** | **委托层 `run_hpc_pipeline()`** ← 本次新补 |

若遗漏 ⇒ 字面 `{nxb}` 直达远端 `setup` ⇒ `int('{nxb}')` 抛错。
**自检**：`assert "{nxb}" not in flags`。

### 4.4 `--skip-build` 的语义边界

| 情形 | `--skip-build` | 原因 |
|---|---|---|
| 派生场景**首次**部署 | ✗ **不可用** | `SNBVTi_ug_obj/flash4` 尚不存在 → 正确中止 |
| 同场景第 2+ 次运行 | ✓ 可用 | 复用已编译二进制 |

这不是 bug，是**正确的防护**（防止误用他场景的 `flash4`）。

## 5. 运行前闸门

`run_hpc` 在提交运行作业**前**会 grep par 校验 SNB 铁律：

```bash
grep -E '^gr_hypreUseFloor[[:space:]]*=' <par> || echo MISSING
```

期望输出 `gr_hypreUseFloor = .false.`。不通过则不提交 —— 这是防
"用旧 par 跑出新崩塌"的关键拦截（见 05_坑位清单 P2b）。

## 8. 失败排查速查

| 症状 | 首查 |
|---|---|
| `单元必需文件缺失: <某.cn4>` | 委托漏网点① → 检查 `glob("*.cn4")` |
| `int() ... '{nxb}'` / 22 s SETUP_FAIL | 委托漏网点② → 检查 `SETUP_FLAGS` 已格式化 |
| `--skip-build 但远端 flash4 不存在` | 首次部署勿加 `--skip-build` |
| 运行前闸门 MISSING | par 陈旧 → 删 `flash_input/*.par` 重新生成 |
| `IONMIX4 file not found` | cn4 表名与文件内容不符（尤其 `CH-BADGER-*`） |
| `Negative 3T internal energy` | 核数过多（>192）；或 `dtmax` 过大 |
| 路由全 REFUSED | 本机无 IPv6 / 通道未开 → 用 `ssh.paracloud.com:2222` 等可达路由 |
