# 03 — 网格分辨率与超算核数

> 回答"**超算核数怎么选才能满足最低分辨率**"。
> 本项目几何：`xmin=-0.04 cm, xmax=0.01 cm` → **域宽 500 µm**；
> 最薄层 **0.1 µm**；物种 8 个（`cham, shld, samp, tar1, tar2, tar3, tar4, tar6`）。

---

## 1. 硬约束的来源

### 1.1 为什么薄层要求 `dx ≤ 0.03 µm`

`Simulation_initBlock.F90` 用**单元中心判据**给单元赋物种：

```
若 单元中心 x_center ∈ 薄层区间  →  该单元物种 = 薄层物种
```

若 `dx > 薄层厚度`，**没有任何单元中心落进薄层** ⇒ 该物种质量分数
恒为 `sim_smallX = 1e-99`（即"从未被写入"）。

后果：相邻两层（密度差可达 6 个数量级）**直接接触** → 一步即爆
（`DRIVER_ABORT: Negative 3T internal energy`）。

⇒ **经验法则**：每薄层至少 **3 格** ⇒ `dx ≤ 0.1/3 = 0.0333 µm`，
本项目取整为 **`dx ≤ 0.03 µm`**。

### 1.2 `+ug` 下网格由核数决定

```
dx = 域宽 / (iProcs × nxb)          ← par 的 nblockx/lrefine* 被无视
```

其中 `iProcs` **必须** == `mpiexec -n`（一块一进程）。

**反推 nxb**（`build_setup_flags_ug` 的算法）：

```python
need = dom / dx_max / nproc                 # 每块最少单元数
nxb  = 2 ** ceil(log2(max(8.0, need)))      # 取 2 的幂
dx   = dom / (nproc * nxb)
```

`nxb` 取 2 的幂是 FLASH `+ug` 的要求。

## 2. 核数 ↔ 分辨率对照表（本项目实测计算）

| ntasks | nxb | dx [µm] | 格/0.1µm 层 | 格/1µm 层 | 总格数 | 判定 |
|---:|---:|---:|---:|---:|---:|---|
| 4 | 8192 | 0.01526 | 6.55 | 65.5 | 32,768 | ✅ 优 |
| 8 | 4096 | 0.01526 | 6.55 | 65.5 | 32,768 | ✅ 优 |
| 16 | 2048 | 0.01526 | 6.55 | 65.5 | 32,768 | ✅ 优 |
| 32 | 1024 | 0.01526 | 6.55 | 65.5 | 32,768 | ✅ 优 |
| 64 | 512 | 0.01526 | 6.55 | 65.5 | 32,768 | ✅ 优 |
| 128 | 256 | 0.01526 | 6.55 | 65.5 | 32,768 | ✅ 优 |
| **131** | **128** | **0.02982** | **3.35** | 33.5 | 16,768 | ⚠ **勉强合格（下限）** |
| **192** | **128** | **0.02035** | **4.92** | 49.2 | 24,576 | ✅ **推荐** |
| 256 | 128 | 0.01526 | 6.55 | 65.5 | 32,768 | ✅ 优 |
| 384 | 64 | 0.02035 | 4.92 | 49.2 | 24,576 | ✅ 良 |
| 512 | 64 | 0.01526 | 6.55 | 65.5 | 32,768 | ✅ 优 |

### 读表要点

1. **`dx` 只依赖 `nproc × nxb` 的乘积**，相同乘积 → 相同 `dx`。
   （128 核×256 = 32,768 与 256 核×128 = 32,768 → 同为 0.01526 µm）
2. **131 核是个"坏点"**：它是**质数**，只能用 `nxb=128`，导致乘积仅 16,768，
   `dx` 退化到 0.02982 µm —— **刚好卡在 0.03 µm 判据边缘**（3.35 格/层）。
3. **192 核**（= 64×3，3 节点 × 64 核）用 `nxb=128` 得 24,576 乘积，
   `dx` = 0.02035 µm，**4.92 格/层** —— 裕度充足，且**节点数少**（排队快）。
4. **256 核**（= 2 的幂）能用 `nxb=128` 达到最优 `dx` = 0.01526 µm。

## 3. 本场景实际配置（截至 2026-09-12）

| 项 | 值 | 备注 |
|---|---|---|
| 分区 | `v5_192` | 48 核/节点 |
| `-N` | 3 | |
| `--ntasks` | **131** | |
| `-nxb` | **128（硬编码）** | ⚠ 与 131 核的自动档**恰好重合**（巧合，非推导） |
| `mpiexec -n` | 131 | ✅ == iProcs |
| 实测 `dx` | 0.02982 µm | 3.35 格/层，**勉强合格** |
| 总格数 | 16,768 | |
| 实测性能 | **0.384 s/step** | |
| 短测耗时 | 58.1 min（`tmax=2e-10`，23 chk） | 9073 步 |

### ⚠ 两个待修正项

1. **`build.sh` 的 `-nxb=128` 是硬编码**。若核数改动，`dx` 会**静默变化**。
   → 应由 nproc 推导（写入 `build.sh`）。
2. **131 核本身不是好选择**（质数 + 3.35 格/层）。
   → 生产跑建议 **192 核**（4.92 格/层，裕度 +47%）。

## 4. 核数选择决策

### 4.1 候选方案对比

| 方案 | ntasks | 节点 | dx [µm] | 格/层 | 相对 131 核加速比* | 评价 |
|---|---:|---:|---:|---:|---:|---|
| 现状 | 131 | 3 | 0.02982 | 3.35 | 1.00× | 勉强合格 |
| **A（推荐）** | **192** | **3** | **0.02035** | **4.92** | **1.47×** | 裕度足、节点不变 |
| B（最优精度） | 256 | 4 | 0.01526 | 6.55 | 1.95× | 精度顶格，多占 1 节点 |
| C（同精度、省节点） | 64 | 2 | 0.01526 | 6.55 | ~0.98× | 精度同 B 但更慢 |

\* 加速比按格数比例粗估；实际受通信开销影响，192 核预期实得 **1.3~1.4×**。

### 4.2 建议

> **生产跑用 192 核**（方案 A）。
> 理由：① `dx` 从 0.02982 → 0.02035 µm，薄层裕度从 3.35 → 4.92 格；
> ② 节点数仍为 3，**排队时间不增加**；
> ③ 相对 131 核有 1.3~1.4× 实际加速。

### 4.3 是否需要再做短时测试？

**需要，且只需一次。** 原因：

1. **131 → 192 核改变了 `dx`（0.02982 → 0.02035 µm）**，
   这属于**网格变更**，不是纯并行度变更。
   - `dx` 变化 → 数值耗散变化 → **前几帧的瞬态会不同**
   - 必须重新验证：8 物种全 nonzero、`dt` 健康、质量守恒
2. 192 核下 `nxb=128` **不再是自动推导的结果**，需要确认 `iProcs=192` 与
   `mpiexec -n 192` 匹配无误。

**推荐测试方案**：

| 项 | 值 |
|---|---|
| `tmax` | `2.0e-10`（与本次短测一致，便于逐帧对照） |
| 核数 | 192（`-N 3`, `--ntasks=192`） |
| `-nxb` | **128**（此时 dx=0.02035 µm，达标） |
| 验收 | ① chk_0000 的 8 物种全 nonzero 且每薄层 ≥3 格<br>② `dt` 平滑无塌陷<br>③ `∫ρ dx` 相对漂移 < 1%<br>④ 与 131 核结果同窗口比对（**按时间戳配对**，非按序号） |
| 预期耗时 | ~40 min（换算自 131 核的 58 min） |

> ⚠ **比对护栏**：192 核与 131 核的 `dx` 不同 → 结果**本就不应逐位相同**。
> 比对目的是确认**物理趋势一致**（ρmax 增长形态、前沿位置量级），
> 不是数值相等。若强行要求相等，说明比对方法错了。

## 5. 完整长时跑的成本估算

按实测 **0.384 s/step** @ 131 核：

| 目标 | 步数 | 131 核 | 192 核（估） |
|---|---:|---:|---:|
| 短测 `tmax=2e-10` | 9,073 | 58 min | ~40 min |
| **生产 `tmax=1.6e-9`** | ~72,600 | **~7.7 h** | **~5.4 h** |

> 注：步数按 `dt ≈ 2.2e-14 s` 平均估算。实际 `dt` 会随密度上升而下降
> （实测 1.11e-14 → 9.0e-15），后期步长变小 → 实际耗时**可能上浮 30~60%**。
> 保守估计 1.6 ns 生产跑留 **8~12 h** 机时。

## 6. 快速核算脚本

```bash
python -c "
import math
dom    = 0.05      # cm
layer  = 0.1e-4    # cm, 最薄层
dx_max = layer/3   # cm
for n in [131, 192, 256, 384]:
    nxb = 2**math.ceil(math.log2(max(8.0, dom/dx_max/n)))
    dx  = dom/(n*nxb)
    print(f'n={n:4d}  nxb={nxb:5d}  dx={dx*1e4:.5f}um  {layer/(dx*1e4):.2f}格/层  total={n*nxb}')
"
```
