# 02 — 端到端流程（SNBOneCH_ml）

> 从零到出图的完整可复现流程，覆盖 **本地 WSL** 与 **超算 NC-E** 两条路径。
> 每条命令都标注**前置条件**与**验收判据** —— 不满足判据不要进下一步。

---

## 0. 总览：7 个阶段

```
① 准备     场景自包含校验（F90 哈希）           → SNB_F90_PROVENANCE.md
② 生成     par 生成 + 网格核算                  → dx ≤ 0.03 µm
③ 部署     场景层 + 树层合并到 SimulationMain   → 8 物种全 nonzero
④ 构建     setup + make                         → flash4 可执行
⑤ 运行     mpiexec -n == iProcs                 → chk 帧数 > 0
⑥ 回收     结果下载（每文件独立连接+并行）       → 字节数校验通过
⑦ 分析     chk 健康检查 + 物理审查              → 守恒量 + rho/dt 判据
```

## 阶段 ② — 生成与网格核算

**par 的权威默认值来源**：`flash/input_gen/gen_par/defaults.py`。
**不得手写基础参数段。**

### 网格核算（★ 最容易出错的一步）

```bash
python -c "
import math
dom = 0.05          # cm, = |xmax - xmin| = 500 um
nproc = 192         # 计划核数
nxb = 2**math.ceil(math.log2(max(8.0, dom/(3e-6*nproc))))
dx  = dom/(nproc*nxb)
print(f'nxb={nxb}  dx={dx*1e4:.5f} um  格/0.1um层={0.1/(dx*1e4):.2f}')
assert dx <= 3e-6, 'dx 超标！薄层物种将不被写入'
"
```

- **判据**：`dx ≤ 0.03 µm` **且** 每个薄层 ≥ 3 格（本项目 0.1 µm 层）
- **本项目对照表**见 `03_网格与核数.md`
- ⚠ **NC-E `build.sh` 目前硬编码 `-nxb=128`** —— 换核数时必须同步改

### par 关键键自检

| 键 | 值 | 为什么 |
|---|---|---|
| `dtmax` | **`2.0e-14`** | SNB 崩塌主因之一，见上游 P2 |
| `gr_hypreUseFloor` | **`.false.`** | ★★★ SNB 崩塌**真正主因**，见上游 P2b |
| `diff_eleFlMode` | `fl_none` | 项目约定（在 SNB 路径上是 no-op） |
| `rt_mgdNumGroups` | `10` | 必须 == setup 的 `mgd_meshgroups` |
| `lrefine_max/min` | `1` | `+ug` 下被无视，置 1 免校验冲突 |

- **判据**：`snb_params.py` 的 `NUMERIC_CRITICAL_KEYS` 硬校验通过

## 阶段 ③ — 部署

**合并两层到 `SimulationMain/SNBOneCH_ml/`。**

优先级（NC-E `build.sh` 已实现）：
1. **场景自包含优先**：`flash_input/` 里有就直接用
2. **树回落**：没有才从 `SNB_1D_laser/` 拷

```bash

      Simulation_initBlock.F90 *.cn4 "$UNIT"/

```

## 阶段 ④ — 构建

```bash

        ed_maxPulseSections=300 -objdir=SNBOneCH_ml_ug_obj
```

## 阶段 ⑤ — 运行

```bash
cd SNBOneCH_ml_ug_obj
cp -f <deploy>/snbonech_ml.par flash.par
sed -i "s/^iProcs.*/iProcs = 131/" flash.par     # ★ 必须 == mpiexec -n
sed -i 's/^tmax.*/tmax           = 2.0e-10/' flash.par
rm -f snbonechug_* wsl_run_snbonech.log
mpiexec -n 131 ./flash4 > wsl_run_snbonech.log 2>&1
```

| 约束 | 内容 |
|---|---|
| `mpiexec -n` | **必须 == `iProcs`**（`+ug` 一块一进程） |
| `tmax` | 运行时用 `sed` 覆写 → **判据看 chk 的 `real runtime parameters`** |
| 日志 | **必须带批次 tag 前缀**（否则 smoke/full 同名，误读旧 `RUN_EXIT=0`） |

- **判据**：objdir 内 `snbonechug_hdf5_chk_*` 帧数 > 0

### 作业完成判定（超算，★ 三处都看）

| # | 查什么 | 说明 |
|---|---|---|
| 1 | `squeue` / `sacct` 状态 | `COMPLETED` |
| 2 | 作业目录 chk 的 **mtime 是否增长** | 真在算 |
| 3 | **objdir 内 FLASH 日志的步进轨迹** | ★ 最关键 |

> ⚠ `run.sh` 把 stdout 重定向进 objdir → SLURM `--output` 文件**永远 0 字节**。
> 曾据此误判"空转"，实际已正常跑完。
> ⚠ `hydra_bstrap_proxy FAILED` 常是**作业被 kill 后的伴随现象**，非根因。

## 阶段 ⑥ — 结果回收

> ★★★ **结果不在 objdir！** `run.sh` 结尾把 chk/plt/profile/log 移入
> `<HOME>/QC/<scene>_deploy/_out/`。直接去 objdir 拉会得到"输出消失了"的假象。

**下载必须遵守 5 条**（两次真实事故换来的）：

| # | 要点 | 为什么 |
|---|---|---|
| 1 | **每个文件独立建连** | 复用会话 → `Server connection dropped` → 全线 `Socket is closed` |
| 2 | `sftp.get_channel().settimeout(1800)` | 10 MB chk 需 ~580 s ≫ 默认 120 s |
| 3 | 4 线程并行 | 单连接 17 KB/s → 4 连接 ~130 KB/s（**7.7×**） |
| 4 | 逐文件**字节数校验** + `.part` 原子改名 | 防半截文件冒充成品 |
| 5 | 以远端 `listdir_attr` 为准 | 不信本地缓存 |

**三个前置坑**：

- ★ 基础托管解释器**缺 `cryptography`** → 凭据解密抛错、脚本**静默退出且日志 0 字节**
  → **必须用 `.venv/Scripts/python.exe`**；排查第一步永远是 `--dry-run`
- ★ `nohup` / DETACHED 起的长任务**被沙箱回收** → 用宿主后台任务机制
- ★ paramiko **不展开 `~`** → 先 `printf '%s' "$HOME"`

- **判据**：`.part` 文件数 == 0，且每个文件尺寸 == 远端尺寸

## 阶段 ⑦ — 分析

### 7.1 健康检查（必做）

| 检查 | 判据 | 不合格含义 |
|---|---|---|
| `dt` 轨迹 | 平滑、无塌陷 | 塌陷 → 时间积分失稳 |
| `rho_max` 单帧变化 | 见下方四项并联判据 | — |
| 体面质量 `∫ρ dx` | 相对漂移 < 1% | 守恒破裂 |
| 薄层物种 | chk_0000 里 8 个全 nonzero | 网格不达标（回到阶段②） |
| 层位置 | tar1/2/3/4/6 在设计位置 | 物种写入错误 |

### 7.2 ★★★ 密度跃变的四项并联判据

**单看 `rho_max` 跃幅会误判。** 2026-09-12 曾把 `+86.1%` 的跃变当成发散，
实为**中心撞击压缩**。四项**缺一不可**：

| # | 判据 | 物理含义 |
|---|---|---|
| ① | `argmax(dens)` **是否始终在对称轴 x=0** | 压缩必在中心；边界/局域尖峰才可疑 |
| ② | `dt` 在跃变时刻**是否下降** | 发散必砍 dt；主链是 hydro 时密度不进 CFL |
| ③ | **内能密度增长是否平滑** | 压缩 = 绝热做功（平滑）；激波加热会在跃变帧出尖峰 |
| ④ | **体面质量是否守恒** | 零源汇则 `∫ρ dx` 逐位相同 |

本轮实测：① x=0.000 µm 全程 ✅ ② dt 平滑 1.36e-13→8.99e-15 ✅
③ 1.04e10→3.10e14 平滑 ✅ ④ 5.611924e-07 逐位相同 ✅ → **非发散**

### 7.3 数据读取的三个陷阱

| 陷阱 | 正确做法 |
|---|---|
| HDF5 键**大小写** | FLASH 写小写（`qesh`/`cogq`）；先 dump 全部键名 |
| `real scalars` 是 **record array** | `d["value"][np.char.strip(d["name"])==b"time"]` |
| `coordinates` 是**块中心** | 逐格坐标由 `bounding box` + `nxb` 重建 |

### 7.4 绘图

- ★ **x-t 图禁用 `imshow`** —— chk 帧间隔不均（实测跨 52.7×），时间轴会被拉偏数千个百分点
  → 必须 `pcolormesh` + 真实逐帧时间坐标
- ★ **不要凭共享色标的 x-t 图目视判断前沿位置**（阈值法实测差 0.37 µm）
- 全英文字符，字号 > 18 pt，DPI ≥ 450
