# 07 — 核心模块与工具（SNB/SNB 作为场景处理中心）

> **本目录 `flash/scenarios/private/SNB/SNB/` 是 SNB 场景处理的唯一核心模块。**
> 场景生成、F90 代码复制、运行、分析、分享前检查，全部以本目录为根。

---

## 1. 两层设计（关键）

本目录同时承担两个互相冲突的职责：
① 是**可分享**的方法文档集；② 是**不可分享**的 F90 实现包本地仓库。
故按目录**显式分层**：

| 层 | 目录 | 内容 | 是否入库 |
|---|---|---|---|
| **可分享层** | `README.md` `docs/` `scripts/` `manifest.json` | 文档、参数参考、场景生成器、运行驱动、分析、分享检查器 | ✅ **入库** |
| **本地保留层** | `source/` `variants/` `tools_local/` | 作者 SNB 实现包、参考版、EOS/opacity 表、示例 par、F90 诊断变体、**会写 F90 的脚本** | ❌ **不入库** |

**为什么必须有本地保留层**：F90 实现包是场景能跑起来的前提，但按分享规则
（与 FLASH License §3）**不得分发**。所以"存在但不入库"是唯一可行方案。

**为什么 `tools_local/` 单独一层**：它里面是 `.py`（扩展名在放行列表里），
但**会写入 F90 源码**，等价于源码本身 → 必须**整目录**排除。
只靠"按扩展名放行/拦截"是挡不住的，这就是目录闸门存在的理由。

## 3. 标准工作流（四条命令）

```bash
cd <flash 包目录>
PY=python
M=flash/scenarios/private/SNB/SNB

# ① 导入/重建源文件（新环境一次性）
$PY $M/scripts/generate/import_sources.py \
      --from <作者SNB实现包目录> --also-stock <限流SH参考版目录>

# ② 生成诊断变体（可选；产物在 variants/，不入库）
$PY $M/tools_local/make_variants.py

# ③ 生成场景（F90 复制 + par 生成 + 受控性自检）
$PY $M/scripts/generate/gen_scene.py --out <场景目录>
#   常用选项:
#     --legs snb,flsh            要生成的腿（默认两条）
#     --radiation on|off|both    辐射开关; both = 每腿生成 开/关 两个 par (2×2)
#                                ★ 默认 **on**（2026-09-12 起，项目约定）
#     --driver-variant radon     ★★ SNB 腿【必须】用 radon（默认）
#                                   (作者原版把 call RadTrans 注释了 → 辐射永不推进;
#                                    用 radon 恢复后 par 三开关才生效)
#     --ele-fl-mode fl_none      ★★ 电子限流模式（默认 fl_none）
#                                   该键在 SNB 电子路径上**实测为 no-op**（逐位相同）;
#                                   见 docs/05 坑位清单 P1 更正块
#     --therm-variant limiter    λ_g 限制变体（需先跑 ②）
#     --flsh-mode native|stock   对照腿用标准树原生 / stock_sh 覆盖件
#     --dtmax 2.0e-14            ★★ 必须 2e-14（2e-12 会非物理崩塌, 见 docs/08）
#     --nxb 128 --iprocs 8 --tmax 0.8e-9
#     --verify-keys-against <作者示例 par>   ★ 键集差分校验（强烈建议）

# ④ 运行（部署 → setup → make → run → 收集）
$PY $M/scripts/run/run_scene.py --scene <场景目录>
#   常用选项:
#     --side snb|flsh|both
#     --par <腿>_radon.par --tag radon    2×2 矩阵下选腿
#     --species a,b,c --tables T1.cn4,... ★ 物种/表清单须与场景一致
#                                           （如 2 标记场景 cham,targ）
#     --pulse-sections 300                多段激光脉冲（如 82 段）必需
#     --skip-setup --skip-make            复用已编译二进制
#         ⚠ 会被"构建指纹"覆盖：objdir 名固定 → 不同场景**复用同一 objdir**，
#           沿用旧 flash4 会把别的场景的二进制当成当前结果（静默错误）。
#           脚本以 flash_input/ 全文件 + setup 参数的 SHA256 记入 objdir；
#           **不一致或缺 flash4 → 无视 --skip-\* 强制 setup+make**。
#     --check-only               只做前置检查（树/源/表/补丁）

# ⑤ 提交前自检（强制）
$PY $M/scripts/check_share_safety.py
```

## 4. 各工具职责与判据

| 工具 | 职责 | 关键判据 / 特性 |
|---|---|---|
| `import_sources.py` | 把作者包**复制**到 `source/`，算 sha256 写 `manifest.json` | **补丁状态校验**：续行符已补、模块名已改、Makefile 含多群权重模块；未打齐则 exit 1 |
| `make_variants.py` | 由作者源码派生 F90 变体（只改注释状态） | 行数必须不变；"生效行数"用**排除注释行**的方式统计（否则 `! <needle>` 会误判为仍生效） |
| `gen_scene.py` | 复制 F90 + 生成 par + 受控自检 | **同侧两腿只应差腿标识 + 辐射三开关**；跨腿仅差腿标识；自动检测 par 重复键 |
| `run_scene.py` | 部署/setup/make/run/收集 | 树自动探测（SNB→FLASHSNB，对照→标准树）；**收集先校验后删**（本地 chk>0 才算成功）；`make` 判据用退出码**不用 `grep error`**；★ **构建指纹**：`flash_input/` 全文件 + setup 参数的 SHA256 记入 objdir → 不符或缺 `flash4` 时**无视 `--skip-*` 强制重建** |
| `compare_4way.py` | 四腿 2×2 对比图 + 定量表 | 数据源 **chk**；`resolve_outdir` 支持任意 tag；产 `pcolor/`+`profiles/`+`ablation/`+`compare/`；★ x-t 用 **`pcolormesh` + 真实逐帧时间坐标**（**不可用 `imshow`** —— chk 的 Δt 高度不均） |
| `chk_probe.py` | **chk 健康检查**（dt 钳位 / 崩塌 / **温度单位自检**） | 判据一律取 **chk 的 `real scalars`**（不看 par 文本）；`dt` 全程钉死=生效、随步增长=必崩；★ `--unit-check` 用 `eint=(3/2)p/ρ` 与 `p=(n_i+n_e)kT` 两条恒等式判定温度单位是 K 还是 eV（P28）；★ `--collapse-drop` 可调崩塌阈值（换材料后需重新标定，P35）；Te 同时以 **K 与 eV** 双列输出 |
| `snb_params.py` | 参数参考 + par 校验 | 内置推荐值表（含 `dtmax=2e-14`、**`gr_hypreUseFloor=.false.`**）；可校验任意 par 的关键设置与群数/白名单 |
| `check_share_safety.py` | **分享前强制自检** | ①类型闸门 ②**目录闸门** ③内容闸门（★ 按**二进制黑名单**扫描，除源码类与明确二进制外一律当文本扫）；待提交集合 = **已暂存 ∪ 未跟踪 ∪ 已修改**；git 查询失败 **fail-closed**（见 `docs/06` §8） |

## 7. 薄驱动模式（推荐的新场景建法）

**新场景不应重新实现任何算法或复制 F90**，而是：

```
t006/run_t006.py                     ← 唯一自有文件（薄驱动）
  ├─ generate : SNB/SNB/scripts/generate/gen_scene.py     (F90 复制 + par 生成)
  ├─ run      : SNB/SNB/scripts/run/run_scene.py           (部署→setup→make→run→收集)
  └─ plot     : SNB/SNB/scripts/analysis/compare_4way.py   (2×2 图 + 定量表)

t006/scene/                          ← 生成物（F90 + par），可随时删除重建
t006/images/  t006/results/  t006/logs/
```

**薄驱动的必备要素**（照 `t006/run_t006.py` 抄）：

| 要素 | 说明 |
|---|---|
| 核心模块定位 | 从自身向上逐级找「名为 `SNB` 且含 `scripts/`+`source/` 的目录」，**不写死层数** |
| 前置检查 | 校验三个脚本存在、`source/` 存在、`variants/Driver_evolveFlash_radON.F90` 存在 |
| `--stage` | `all` / `generate` / `run` / `plot`，便于分步 |
| **`--dtmax` 默认 2.0e-14** | ★★ 硬性；不得沿用任何模板文本 |
| **`--driver-variant` 默认 radon** | ★★ SNB 腿需要；否则辐射开关失效 |
| 每侧只 setup/make 一次 | 首条腿部署编译，第二条腿 `--skip-deploy --skip-setup --skip-make` |
| 分层输出 | `scene/`（生成物）、`images/`（图）、`results/`（表）、`logs/`（日志）分开 |

**这是对核心模块的端到端验证**：若薄驱动能一次跑通四腿且受控性自检通过，
说明核心模块自包含、可复用。

## 8. 数据判读铁律（2026-09-14 新增；详见 `docs/05` 的 P28–P35）

> 三条"看数据"的铁律。**违反任一条都会得出与事实相反的结论** —— 本轮三条都踩过。

### 8.1 温度单位：chk 里是 **K**，不是 eV

`tele` / `tion` / `trad` / `temp` 均为**开尔文**。显示为 eV 须 `/11604.51812`。

**先自检，再下结论**：`scripts/analysis/chk_probe.py --unit-check` 用两条独立恒等式判定——
① `eint = (3/2)·p/ρ`（识别量纲错；偏离 >10× 才是错，含电离能时会偏百分之几）；
② `p = (n_i+n_e)·k·T` —— **只有 T 取 K 才与 chk `pres` 吻合**（实测 1.4%），取 eV 差 **1e4 倍**。

★ 反例：姊妹模块 `_longrun_lib.py` 曾把常量写成 `1.16045e7`（实为 **K/keV**，大 1000 倍）
→ 温度少 1000 倍；且绘图脚本**只有一处**换算、另三处标注 eV 但用 K 原值 ⇒ 同一份数据在不同图里差 1160 倍。
**单位常量集中定义 + 附量纲注释，禁止就地写裸字面量。**

### 8.2 能量收支：必须 `∫ρ·eint dx`

`eint` 是**比**内能 [erg/g]，故能量面密度 = `∫ρ·eint dx`。
漏乘 ρ 会把 `9.08e11 erg/cm²` 报成 `6.0e13`（**假超支 20 倍**），并连带把"左半域占比"从 46.6% 报成 72.6%。

**量纲自检**：任何收支结论都要与已知输入比量级 —— 激光侧用 `LaserEnergyProfile.dat`
（列义见表头：`Step, Time(s), dt(s), Energy in(erg), Energy out(erg), dE in, dE out`）。

### 8.3 性能：只读 `perf_summary` 的 `num calls` 列，**绝不数日志行**

日志只打印**部分**调用（受 `gr_hyprePrintSolveInfo` 等门控）。
实测 `gr_hypreSolve` **5,692,647 次 = 每步 19.0 次**，占总墙钟 **76.8%**
（其中 `HYPRE_ParCSRPCGSetup` 60%）；而按"日志行数 ÷ 步数"会算出 **0.038 次/步 —— 错约 500 倍**。

★ 取法：运行末端的 `perf_summary` 段（`tail -120 <objdir>/<log_file>`）。

### 8.4 判定"崩塌"：以**与已验证基线同窗口比对**为准

单指标阈值（如 ρmax 单帧跌幅 >30%）**换材料/换几何后会假阳性** —— 见 P35（SNBVTi 实测 31.0%，
但与基线逐点一致）。最终判据：与基线逐点/逐位比对，或 `rho_sum` 出现 NaN。

## 9. 生产级长跑流水线（`scripts/longrun/`）派生时必须处理的四条坑

各场景可自带 `scripts/longrun/` 生产编排（generate → submit → wait → fetch → plot，断点续跑）。
**派生新场景**时：

| # | 坑 | 处置 |
|---|---|---|
| 1 | **场景标识硬编码**：`import SNBVTi as M`、`SCEN_DIR/"SNBVTi.py"`、`wsl_run_snbvti.log`、`snbvti.par` | 收敛成单一来源：`SCEN_MODULE = SCEN_DIR.name` + `importlib.import_module(SCEN_MODULE)`；文件名由 `M.BASENM` / `M.PAR_FILENAME` / `M.LOG_FILE` 派生（P32） |
| 2 | **远端 wrapper 日志名由原语模块决定**（不由本场景决定） | 委托架构下 `run_hpc` 生成的是**参考模块**的日志名 ⇒ 按 glob `wsl_run_*.log` 匹配，**不要按固定名**（否则日志永远取不到，表现为"未找到 wsl_run_*.log → 跳过 dt 演化图"） |
| 3 | **重复提交**：父进程网络死亡后远端作业仍存活，重提会双开同一 objdir | 提交前查 `squeue` 同名 run 作业 → **rc=2 中止**（`--allow-duplicate` 逃逸）；进度探针**收全部队列行**（P33） |
| 4 | **下载截断 / 共享会话挂死** | 线程池之后加**顺序收敛遍**（重下尺寸不符者 + md5 双闸门）；挂死则终止后重跑（幂等续传）（P31） |

**另**：`longrun` 的 `--skip-build` 依赖 `_BUILD_STAMP.json` 构建指纹，指纹**故意不含 par**
（par 是运行时参数）。**改了 `Config` 的编译期常量（如物种数）→ 指纹必变 → 自动全量重编**；
但**不能只看 `flash4` 是否存在**（见 P25 第三课、`docs/05` P34）。
