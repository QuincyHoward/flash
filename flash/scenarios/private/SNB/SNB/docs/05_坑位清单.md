## 物理 / 数值类

### ★ P1 — 电子限流器设成"无限流"会破坏守恒

| 项 | 内容 |
|---|---|
| 现象 | 内能 / 激光注入能量 达 **13×**（物理应 ≤ 1）；总面密度先崩落再"恢复" |
| 根因 | 某些限流模式下，限流因子被置 1 且**不改电导** → 陡梯度处电子热流取**无界 Spitzer 值** |
| 处置 | 见下方更正块 —— 在 **SNB 配置**下该键是 no-op，**不构成处置手段** |
| 教训 | 短时运行（≤1e-10 s）**不会暴露**该问题，必须用**长脉冲 + 积分守恒量**才能发现 |

> ### ★★★ 2026-09-12 更正 —— **该条目在 SNB 配置下不成立**
>
> **实测**（`t006/flnone_test`，单变量 A/B，全长 0.8 ns × 17 帧）：
> 把 `diff_eleFlMode` 从 `"fl_harmonic"` 改为 `"fl_none"`，
> 六个物理量（dens / tele / tion / trad / pele / pres）的逐帧最大绝对差
> **全部为 `0.000000e+00`** —— **逐位相同**（短时腿 t=1e-11 亦同）。
>
> **原因**：`source/snb_package/diff_advanceTherm.F90` 的**各向同性电子分支**中，
> 限流器调用（`:839`）与 SH 传导解（`:847`）**均被注释掉**；
> 而本类场景 `diff_anisoCondForEle = .false.` → **不进入**各向异性分支，
> 即 `:818` 那个唯一还活着的电子限流调用点也不进入。
> ⇒ `diff_eleFlMode` 在电子路径上**没有任何存活的消费者**。
>
> **因此**：
> - 上表的 13× 观察**必然来自其它配置** —— 非 SNB 的限流 SH 腿
>   （那里 `source/stock_sh/diff_advanceTherm.F90:317` 的限流调用是**活的**），
>   或某个开启了各向异性的构型。**切勿**把 `fl_harmonic` 当作
>   "保护 SNB 守恒的措施"来引用。
> - 真正保护 SNB 腿的是 **SNB 多群非局域公式本身** +
>   `gr_hypreUseFloor = .false.`（见 P2b）。
> - **项目约定默认 `diff_eleFlMode = "fl_none"`**（`snb_params.py` 已改）。
>   它是**声明意图**：对**离子**腿（`:991` 用 `diff_ionFlMode`）与 `FLLM_VAR`
>   诊断量仍有作用，但**不是**承重设置 —— 改回 `"fl_harmonic"` 不会改变 SNB 结果。
>
> **详见**：`SNBtest/Test/t006/docs/对比_SNB3_SH2.md` §2、
> `t006/flnone_test/results/flnone_vs_harmonic.md`。

### ★★ P2 — `dtmax` 过大会非物理崩塌（本清单最高优先级）

| 项 | 内容 |
|---|---|
| 现象 | ① 早期即 `DRIVER_ABORT: Negative 3T internal energy`；② 或**中期崩塌**：ρmax 冲高后骤降、**总质量变 NaN**、Te_max 冲到 4000 eV |
| 根因 | 时间积分步长上限过大 → 陡峭瞬态单步过冲 → 正反馈放大 → 守恒破裂 |
| 处置 | **`dtmax = 2.0e-14`**（充分，不是"延后崩塌"） |
| 对照 | `2e-12`：8.2 ps 中止 **或** 500 ps 崩塌（ρmax→0.26）；`2e-14`：跑满 0.8 ns（ρmax→12.11） |
| 注意 | 与限流器/λ 限制**无关**；与网格分辨率**无关**（粗网格同样崩） |
| ★★ **判据** | **看 chk 的 `real scalars` 里 `dt` 实测值，不看 par 文本**：<br>· `dt` **全程钉死**在常数 → 生效 ✅<br>· `dt` 随步进**增长** → 未生效 ✗ → 必崩 |
| ★★ **易错点** | **输入模板 par ≠ 实际执行 par**。实际执行的那份在 `flash_output/<tag>/par_*.par`。两者矛盾时以**后者**及 **chk 的 `dt`** 为准 |
| 详见 | `08_故障案例_SNB崩塌.md`（完整错误说明与复现验证） |

### ★★★ P2b — `gr_hypreUseFloor` 未写入 → SNB 非物理崩塌（**本清单最高优先级**）

> **2026-09-12 由 t006 从零重建时 A/B 实测定稿。这是 SNB 崩塌的**真正主因**。**

| 项 | 内容 |
|---|---|
| 现象 | SNB 腿 ρmax 冲高到 ~10.5 后**崩塌到 0.26**；总质量相对漂移 ~0.59（守恒破裂）；Ṁ 大 65×。**FL-SH 腿完全正常** |
| 特征 | **第 1 帧（0.05 ns）就已分叉**（ρmax 1.738 vs 2.845，差 1.64×）→ 属初始/求解器配置问题 |
| 根因 | `gr_hypreUseFloor`（HYPRE 隐式扩散求解器 floor 开关）**FLASH 默认 `.true.`**，而本场景应显式设 **`.false.`**。默认值使 SNB 多群热流的隐式扩散解失真 → 过度压缩 → 崩塌 |
| ★ 为何久未发现 | 该键曾被 `gen_scene.py` 的 `_KEY_DIFF_IGNORE` **列入忽略清单** → 键集校验报"183 键 / 缺物理相关 0"通过，而物理已失真 |
| **处置** | `snb_params.py` 的 CONDUCTION 块显式写入 **`gr_hypreUseFloor = .false.`** |
| **决定性证据** | 单变量 A/B：仅加此一键（`.true.`→`.false.`）即把 ρmax@0.05ns 从 **2.845451 → 1.738337**，与成功基线**逐位相同**（6 位有效数字全等） |
| ★★ 配套修正 | ① 从 `_KEY_DIFF_IGNORE` **移除**该键；② 新增 `NUMERIC_CRITICAL_KEYS` **硬校验**（独立于忽略清单，缺失即报错） |
| ★★ 教训 | **"键集校验通过" ≠ "配置正确"。** 忽略清单一旦放行物理相关键，校验即形同虚设 —— 忽略项必须靠 **A/B 实测**确定无害 |
| 详见 | `08_故障案例_SNB崩塌.md` §0 / §3.1 |

> ⚠ **与 P2 的关系**：`dtmax = 2e-14` 是**必要条件**（不是充分条件）。
> t006 在 `dtmax` 正确钳位（`dt` 全程 2.000e-14）的情况下**仍然崩塌**，
> 证明主因是 P2b 而非 P2。两条都要满足。

### ★ P3 — 网格越细，启动瞬态越难

| 项 | 内容 |
|---|---|
| 现象 | 同一几何，dx≈9.4 µm 能勉强推进到 200 ps；dx≈0.29 µm **8 ps 即中止** |
| 根因 | 密度跳变界面越锐，初始瞬态越陡 |
| 处置 | 必须配合 P2；必要时先在粗网格验证，再细化 |
| 备注 | 所有失稳热点常出现在**激光入射口**（能量沉积边界），而非靶面 |

### P4 — `plot_var` 编译期硬上限 = 12

| 项 | 内容 |
|---|---|
| 现象 | 第 13 项起**静默忽略**（日志只出现 `ignoring unknown parameter`） |
| 根因 | `IO/IOMain/Config` 只声明 `plot_var_1..12` |
| 处置 | 白名单 ≤ 12 且**从 1 连续编号**；需要更多量就用 **chk** 读 |

### ★★ P5 — 辐射被静默关闭（SNB 侧"辐射永不推进"）

| 项 | 内容 |
|---|---|
| 现象 | SNB 腿把辐射三开关设 `.true.`，`trad` **纹丝不动**（与初值同量级） |
| 根因 | 作者 `Driver_evolveFlash.F90` 的两处 `call RadTrans(...)` 被**注释** → 辐射求解器**从不被调用**，par 三开关形同虚设 |
| 判据 | `trad` 末帧 ≈ 初值（0.04 eV）而对照腿达 60+ eV，差可达 **1700×** |
| **处置** | ★ **SNB 侧必须用 `--driver-variant radon`**（恢复 `call RadTrans`），**再用 par 三开关**开/关辐射 |
| 受控性 | 同侧两腿使用**同一份 radON 驱动**，仅 par 三开关不同 → "辐射"是唯一变量 |
| ⚠ 反向陷阱 | **不要**以为"改回作者原版就对了"——那样 SNB 侧 `radON`/`radOFF` 两腿将**毫无区别**，2×2 矩阵失去意义 |
| 佐证 | t004 成功的部署单元 md5 `9fe4e2ee…`（18,425 B）**就是 radON 变体**，且 `Trad_max` 达 68.5 eV / 关辐射 0.047 eV |
| 详见 | `04_辐射开关.md` §2（含两版错误结论的更正） |

### P6 — cn4 表温度网格下限

| 项 | 内容 |
|---|---|
| 现象 | 冷启动场景状态不一致 / EOS 报警 |
| 根因 | 表温度下限（如 2.0 eV ≈ 23200 K）**高于**初值（290 K ≈ 0.025 eV）→ 被钳位 |
| 处置 | 选下限 ≤ 0.01 eV 的表族；**换表后建议重新做短时验证**（不同表可能改变稳定性） |

### P7 — 群数必须处处一致

| 项 | 内容 |
|---|---|
| 现象 | setup 报错或运行异常 |
| 根因 | `rt_mgdNumGroups` ≠ `mgd_meshgroups`；或不同物种的 cn4 表群数不同 |
| 处置 | 统一群数；`rt_mgdBounds` 需 **N+1** 个边界对应 N 群 |

## 网格 / setup 类

### P8 — `+ug` 忽略 `nblockx`/`lrefine*`

| 项 | 内容 |
|---|---|
| 现象 | 改了 par 的 `nblockx`/`lrefine` 完全没效果 |
| 根因 | `+ug` 明文忽略这些参数，**一块一进程** |
| 处置 | 分辨率改用 `-nxb` 或 `iProcs`；par 里把 `lrefine_*` 置 1 以免校验冲突 |

### P9 — 非固定块模式必须显式 `-nofbs`

| 项 | 内容 |
|---|---|
| 现象 | 只"不给 `-nxb`"时，par 的 `iGridSize` 被**静默忽略**（实测 iProcs=8 → 只 64 格） |
| 根因 | FLASH 默认仍定义 `FIXEDBLOCKSIZE` 且 `NXB=8` |
| 处置 | 显式加 `-nofbs`；注意它会强制并行 HDF5 IO，与 `+serialIO`/**`parallelIO=False`** 冲突（SETUPERROR） |

### ★ P10 — `mpiexec -n` 必须严格等于 `iProcs`

| 项 | 内容 |
|---|---|
| 现象 | 挂死或错误结果 |
| 根因 | `+ug` 一块一进程 |
| 处置 | 两者保持一致 |

### P11 — plot/chk 的 step 与 time 是 **OR 双触发**

| 项 | 内容 |
|---|---|
| 现象 | 明明设了时间间隔，却额外输出很多帧 |
| 根因 | `plotFileIntervalStep` 与 `plotFileIntervalTime` 任一满足即触发 |
| 处置 | 想只按时间触发 → **注释掉 step 那一行**（不是设大值，是整行注释） |

### P12 — par 生成器的占位行会重复键

| 项 | 内容 |
|---|---|
| 现象 | par 里 `basenm` / `log_file` 各出现两次 |
| 根因 | 生成器头部硬编码了占位值，场景 set() 后又写一份 |
| 处置 | 生成后**注释掉头部占位行**；并在自检里断言**无重复键**（FLASH 取后者，重复有歧义风险） |

### P13 — 新增 VARIABLE 必须重新 setup + make

| 项 | 内容 |
|---|---|
| 现象 | 新变量在输出里找不到 |
| 根因 | `Config` 的 `VARIABLE` 在 setup 期生成索引，编译期固化 |
| 处置 | 改 `Config` → **必须重新 setup 并 make** |
| 对比 | 仅改 `plot_var` 白名单是**纯运行时**的，**不需重编**（前提：目标量已在 objdir 的头文件里） |

## 数据 / 工程类

### ★ P14 — 优先用 chk 而非 plt

| 维度 | chk | plt |
|---|---|---|
| 键数（实测 512 格） | **71** | ≈25 |
| 变量上限 | 无 | `plot_var` 上限 12 |
| 精度 | **float64** | float32 |

**布局**：`+ug` 均匀网格下 chk/plt 布局相同，且**所有块都是叶子块**
（`node type` 是每块标量 = 1）→ **无需 leaf 过滤**。
`coordinates` 是**块中心**；重建节点坐标须用 bounding box 线性插值，
拼接时**每块左闭右开**。

> ⚠️ 通用 FLASH 读取器（如 yt 路径）的**默认模式可能混入非叶子父块**，
> 在物性界面产生陈旧粗网格伪影 → 剖面分析务必只用叶子块。

### P15 — `make` 判定别用 `grep error`

源文件名里含 `error` 会造成误报。用退出码或 `test -x flash4`。

### P16 — WSL 内联命令里禁用 shell 变量

| 项 | 内容 |
|---|---|
| 现象 | 脚本里 `OUT=...; cp x $OUT/` 中 `$OUT` **展开为空** → 文件被写到**盘根目录** |
| 根因 | 双层 shell 展开（外层先展开 `$var` / `$(...)` / 循环变量） |
| 处置 | WSL 内联命令**一律用显式绝对路径**；需要变量时把脚本**落盘**再 `wsl bash <file>` |
| 附带 | `$?` 在该环境下不可靠 → 条件判定改 `if/else` 并落盘标记 |

### P17 — 输出收集要先校验后删除

| 项 | 内容 |
|---|---|
| 现象 | 收集"成功"但本地没有数据 |
| 根因 | `cp ... 2>/dev/null; rm -f ...` —— 复制失败被吞掉，源文件已被删 |
| 处置 | 复制**不吞错**；以**本地 chk 帧数 > 0** 为成功判据；**成功后才删** |

### P18 — 运行日志名必须带批次前缀

| 项 | 内容 |
|---|---|
| 现象 | 短测（smoke）与正式跑的日志同名，旧日志里的 `RUN_EXIT=0` 被误读为本次已完成 |
| 处置 | 日志名包含 tag 前缀；判读完成一律**以 chk 帧数为准** |

### P19 — 绘图时共享色标的陷阱

| 项 | 内容 |
|---|---|
| 现象 | 两腿量值跨 >10 个数量级时，弱的一腿**全黑**，看不出结构 |
| 实例 | 辐射温度：一腿 ~1e12 erg/cm³，另一腿 ~1e-5（差 17 个数量级） |
| 处置 | 提供"逐腿定标"模式，并在标题标注该腿数值区间；**逐腿版文件名必须与共享版区分**（否则静默覆盖） |

### P20 — matplotlib ≥3.9 移除了 `cm.get_cmap`

用 `plt.get_cmap(...)` 或 `matplotlib.colormaps[...]`。

### P21 — `imshow` 的 `extent` 要给时刻端点

不给 `extent=(x0,x1,t0,t1)` + `origin="lower"`，y 轴会退化成帧号。

### ★★ P23 — 排查配置类故障的三条纪律（血泪）

| 纪律 | 反例（曾犯） | 正确做法 |
|---|---|---|
| **① 先穷尽比对，再解释** | 发现两个文件"看起来不同"就把差异当根因（实际该文件两场景**逐字节相同**） | 先对所有同名文件做 **`hashlib` 哈希比对**，确定"到底哪些文件真的不同"，再解释 |
| **② 单变量对照** | t005 用了 radON 驱动且崩塌 → 归因 radON（未做对照） | 排除某变量时**必须做单变量对照**（改回 `none` 仍崩 → 排除） |
| **③ 看实测，不看文本** | 依据 par 文本判定 `dtmax`（实际被命令行覆写） | 判运行时配置**一律读 chk/dat 的实测值** |

**辅助启发式**：若**同一现象在多条腿同步出现**，根因通常在**这些腿共有的路径**上
（t005 的 radON/radOFF 崩塌幅度几乎相同 → 与辐射无关）。

### ★ P24 — 编译期常量无法用 par 改

| 项 | 内容 |
|---|---|
| 现象 | 用 par 覆写某键 → 立即 `Driver_abort`，报 `set: Can not change name with constant attribute` |
| 实例 | `diff_anisoCondForEle`（setup 期定，运行期只读） |
| 处置 | 该类键只能改 setup 标志并**重新编译**；**不能**用 par 做 A/B 测试 |
| 附带价值 | 该报错是**有效的排除证据** —— 证明该键不是两腿差异的来源 |

## 平台类

### P22 — 超算作业脚本的坑

| 项 | 内容 |
|---|---|
| `--output=~/dir/x` 不展开波浪号 | 输出落到字面 `~` 目录、marker 校验全空 → **一律用相对路径** |
| 凭据路由键 | 多账号环境下凭据的 `route_key` 与登录名**可能不同**，裸比较会**静默误路由**到另一个集群（同密码登录"成功"难察觉）→ 用路由判定函数 + `whoami` 核验 |
| 运行库缺失 | 某些 gcc 版本的 lib64 缺 `libgfortran.so.5` → 需在 `LD_LIBRARY_PATH` 补 miniforge 的 lib |
| 模块清理 | 作业里 `module purge` 会清掉编译器环境变量 → 需在作业脚本里重新 source setvars |
