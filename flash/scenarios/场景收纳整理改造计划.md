> **改造结论**：`flash/scenarios/` 下任意场景子目录现已支持**在 scenarios 树内任意移动、重新归类、任意深度嵌套，无需任何修改**，不影响场景目录内全流程脚本（`run.py` → 输入生成 → FLASH 运行 → 分析）的执行。

## 一、可移植化架构（四条支柱）

| 支柱 | 机制 | 效果 |
|---|---|---|
| **全树发现** | `core/discovery.py` 递归扫描 scenarios 全树的 `scene*.json`（排除产物/缓存/备份目录） | 场景放在任何层级、任何新建分类目录都会被发现 |
| **路径三级解析** | manifest 的 `module`/`script`/`hpc.*` 支持：显式绝对（兼容）→ **显式相对**（`".VTi1"`、`"./x.py"`，相对 manifest 位置）→ 缺省自动派生 | manifest 字段随场景目录移动自动跟随 |
| **根定位入口** | `core/scene_paths.py` 的 `repo_root()`/`scenarios_root()`（向上搜 `pyproject.toml + start_flash.py`） | 场景脚本不再依赖 `parents[N]` 层级假设 |
| **按名引用** | 代码复用：`common/scene_ref.py` 按场景名加载；数据文件：`core/anchors.py` + `_scene_anchors.json` 逻辑锚点 | 场景间引用与彼此的物理位置彻底解耦 |

### 场景独立性原则（2026-11-04 追加要求）

- **场景之间零 Python import**：任何场景 .py 不得 import 其他场景的模块（审计强制校验）。
- **代码级复用** → `flash/scenarios/common/`（非场景共享包，位置固定、永不移动）：
  - `scene_ref.scene_module(name, stem)`：按场景名（scene.json 的 `name`）加载对方主模块，进程内单实例缓存（SNB 族"重绑定委托"语义保持不变）；
- **共享基建**（如 `RemoteSession`）→ 直连框架层 `flash.flash_run.remote.session`；
- **数据文件跨场景引用**（如 SNB 族共用 t001 的 source_patches）→ `_scene_anchors.json` 逻辑锚点，`relocate_scene.py` 移动目录后自动重写。

## 二、工具链（`flash/scenarios/scripts/relocate/`，全部幂等可复用）

| 工具 | 用途 |
|---|---|
| `audit_portable.py` | 全树可移植性审计（AST 判定代码/注释；ERROR/WARN/INFO 分级）。`--strict` 有 ERROR 即退出码 1。**任何目录整理前后都应跑一遍** |
| `make_scene_portable.py` | 批量可移植化改造：`manifests`（scene.json 字段相对化）/ `parents`（parents[N]→搜根 bootstrap 或锚点）/ `initfiles`（补 `__init__.py`） |
| `decouple_imports.py` | 跨场景 import 解耦迁移（包路径 import → scene_ref 按名加载 / 框架层直连） |
| `relocate_scene.py` | **收纳整理执行器**：`python relocate_scene.py <src> <dst>` = git mv + 自动创建新分类父目录 + 锚点表重写 + 子树内自指路径改写 + 全树残留扫描 + 后置校验 |
| `verify_all_scenes.py` | 全场景静态批量验证（发现/导入/脚本定位/锚点，秒级），`--json` 出报告 |

## 三、日常操作指引

### 移动一个场景到新分类目录（零手工修改）

```bash
python flash/scenarios/scripts/relocate/relocate_scene.py \
    flash/scenarios/public/center_evolution/ch_center \
    flash/scenarios/public/laser_ch/ch_center
```

工具自动完成：`git mv`（保留 history）→ 锚点表重写 → 子树内 docstring 路径同步 → 残留报告。之后照常：

```bash
cd flash/scenarios/public/laser_ch/ch_center && python run.py --tmax 1e-11
python -m flash.scenarios.core.cli run ch_center --tmax 1e-11   # 场景名不变, CLI 不受影响
```

### 移动整个场景族（如 SNB 全家）

同样一条命令，src 填族根目录（如 `flash/scenarios/private/SNB`）。族内相对布局整体保持，引用自动跟随。

### 目录整理后的标准验证序列

```bash
python flash/scenarios/scripts/relocate/audit_portable.py --strict     # ERROR 必须为 0
python flash/scenarios/scripts/relocate/verify_all_scenes.py --strict  # 必须 35/35
python -m flash.scenarios.core.cli list                                # 场景清单
python -m flash.scenarios.core.cli run <场景> --tmax 1e-11             # 抽查动态冒烟
```

## 五、约定与注意事项

1. **场景名（scene.json `name`）是全局唯一身份**，跨场景引用按名解析 —— 移动/归类**不要改 name**；改动前跑 `verify_all_scenes.py` 确认无重名。
2. **`scene.json` 字段一律用相对形式**（`".xxx"` / `"./x.py"`）；写绝对包路径会被 audit 判 ERROR。
3. **产物目录约定不变**：engine 型运行目录仍固定在 `scenarios/public/runs_<name>/`（与场景位置解耦）。
4. **`scripts/`、`core/`、`common/` 是固定共享区**，不会随场景收纳移动；审计对其中 `parents[N]` 引用仓库根的写法不报警。
5. **超算远端布局**：部分锚点（如 `SNB.snb_package`）描述远端树布局，本地不存在属正常（verify 报 WARN 不报 FAIL）；远端树与本地同步重排后布局自然一致。
6. **新增场景** = 建目录 + 落 `scene.json`（字段可全部省略交由派生）+ 跑 `initfiles` 补包标记，无需注册。
